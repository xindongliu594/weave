# 当前项目雏形

2026-10-01，按用户“有些功能后面再加，当前先把一个项目雏形做出来”的要求收拢本轮范围。首个演示由用户选择 Todo API 代码任务。

## 本轮交付

保留已有部门、员工、模型配置、项目方案、权限、预算、运行追溯和文件交接。增加一条独立启动的 Todo 示例路径：

1. 启动工作台，直接看到项目经理、开发员工、测试员工和已校验的两项任务。
2. 用户查看分工、文件合同和验收标准，再批准项目。
3. 开发员工写出 `todo.mjs`、`smoke.test.mjs` 和 `README.md`，申请实际运行开发自检。
4. 用户批准第一条命令；通过之后，测试员工取得已验收的确切文件版本，写出独立 `acceptance.test.mjs` 和审查记录。
5. 用户批准第二条命令；实际 HTTP 验收检查健康状态、完整 CRUD、参数校验、无效 JSON、不存在的 Todo 和未知路由。执行器依据实际退出码和 TAP 输出生成 `test-report.json`。
6. 员工提交验收，宿主核对命令、文件版本和报告，再完成项目。用户可以预览、下载六个文件和导出完整追溯。

经理和员工使用现有独立 Host、DSH 工具循环、AgentTeams 依赖调度与产品审批接口。API、数据库迁移、费用归属、会话档案、文件合同和原生 Node HTTP 测试实际运行。模型是本地固定响应服务，不生成开放式代码，也不代表真实模型的业务质量。

## 启动与停止

需要 Node.js `^22.19.0 || >=24`。首次安装锁定依赖需要网络：

```sh
npm ci
npm --prefix services/agent-runtime ci
npm run demo
```

打开 `http://127.0.0.1:4320`，点击首页的“查看 Todo 示例方案”。Windows 可在安装依赖后双击仓库根目录的 `start-demo.cmd`。

端口占用时可以指定另一个端口：`npm run demo -- --web-port=4322`。不会停止已有服务。API、数据库和固定模型服务仅监听随机本机端口；网页只监听 `127.0.0.1`。

Ctrl+C 关闭网页服务、员工宿主、固定模型和演示数据库。每次启动创建 `.data/demo/<UUID>`，内含数据库、演示凭证、运行记录及成果；不读取正式数据库和密钥，不自动删除旧演示文件。下一次启动创建新空间，不自动恢复上一轮任务。运行中刷新网页只读取状态，不重新执行项目。

演示不连接真实中转站；其网关修改接口拒绝外部地址，不能导入正式备份。文件写入仅接受仓库内预置 Todo 源码，命令仅允许 `node --test smoke.test.mjs` 与 `node --test acceptance.test.mjs`，仍走逐次审批。测试在单个 Node 测试进程内运行本机临时 HTTP 服务，不执行任意 shell。正式 Docker 和获授权桌面设备的执行路径继续保留。

要切换到本机真实 API 配置，使用 `npm run local` 或 Windows `start-local.cmd`，打开 `http://127.0.0.1:4310/#models`。该入口不需要 Docker，使用持久数据和真实本机执行组件；数据与演示分开保存。详见 [本机运行](local-run.md)。

下载代码后将 `todo.mjs`、测试文件和 `README.md` 放在同一个目录。运行 `node todo.mjs`，默认访问 `http://127.0.0.1:3000/health`；Todo 数据暂存内存，重启后清空。

## 验收

```sh
npm run build
npm run demo:check
```

`demo:check` 使用与交互入口相同的演示 API 和员工执行器，自动批准两条固定测试命令，核对不同员工的宿主、文件交接、独立审查、实际六项验收、六个交付物及零费用；同时验证非预置代码、越界文件、任意命令、外部网关和正式备份被拒绝。结果写入本次演示目录的 `verification.json`，完成后关闭服务。该检查不证明真实 PostgreSQL 多连接锁、真实模型质量、桌面设备配对或线上部署。
