## 用户明确要求登记的变更

### R1：调整员工运行时架构

- [x] 改为每位经理/员工拥有独立运行时宿主，各自管理执行状态与上下文，由部门层协调；本地实现与模拟验证完成，真实模型和部署验收仍待完成。
- 用户原话：“那这个也要改，你给我记上，包括你前面说的桌面的操作能力。”
- 当前实现：每个 Run 创建部门协调 Host，通过公开 AgentFactory 接口为经理和每位员工创建独立 Host；Session 服务、上下文组装和执行循环由各 Host 管理，协调层保留审批、任务、消息、预算、权限和交接。各 Host 仍在同一 Node 进程，详见 [实现与验收边界](employee-runtime.md)。
- **用户已确认方案：**“每个员工独立运行时（推荐）：各自管理执行状态和上下文，部门层负责协调”。经理作为 Agent 也使用独立运行时。独立进程/容器是进一步的实现选项，不是本次已确认的要求；不能将现有独立会话标记为已经满足独立运行时需求。
- 已实现现有任务、消息、文件交接、取消和恢复的宿主边界；自动摘要、工具结果缩减等进一步上下文管理仍属 C1。
- 调整时保留已有的批准快照、员工权限、任务依赖、费用归属、全局/部门预算和执行追溯。长期保留员工配置不等于要求所有员工进程永久驻留。
- 已核实锁定 DSH 的公开 AgentFactory、注册表和子 Agent drain 接口；AgentTeams 的原生续接生命周期通过该工厂创建与恢复独立宿主，未修改安装依赖或复制调度器。
- 验收须证明：员工的上下文和运行状态不会混用；取消、故障与恢复遵守选定的隔离边界；跨员工通信和任务交接可追溯；并发运行仍遵守共享预算及权限。若选进程/容器隔离，另验证进程故障和文件访问边界。

### D1：增加桌面本机操作能力

- [ ] Windows 优先，同时支持 macOS；桌面端能够在用户自己的电脑上执行获授权的工作。
- 当前实现：Electron 远程工作台客户端，连接 Mac 后端；不包含本机 Agent 执行组件，也不能直接操作用户 Windows 的文件、浏览器或应用。
- 目标范围：用户选择本机目录；本地文件读写与交付；调用本地命令和工具；浏览器操作；桌面应用的必要交互。按具体任务分批实现并分别标注支持范围，不以文件工具代替全部桌面能力。
- 待设计：本地执行组件与 Mac 后端的协作、设备身份和员工绑定、系统权限与操作授权、执行状态回传、断线取消与重连，以及结果未知时的核对。
- 浏览器、应用接口或命令行能完成的操作优先采用相应接口；需要界面交互的场景再接入桌面自动化。屏幕读取、键鼠控制的系统授权需要分别验证。
- 桌面动作进入现有任务/员工/运行追溯；共享本机应用、窗口和文件时需要协调，独立员工运行时不代表这些外部资源天然隔离。
- 验收须在真实 Windows/macOS 上证明授权范围、文件和应用操作、取消、断线及重连行为；安装包启动和远程页面可用不能作为本机操作验收。
