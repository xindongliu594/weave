### 实施与验收顺序

1. 先稳住目标、上下文与容量边界；公司级目录和实际引用登记是学习闭环的第一批功能。固定 Eval 案例同时建立。
2. 接通工作节点、引用与生命周期，验证新流程登记、部分复用、成功复用和恢复去重。
3. 记忆插件在隔离环境通过后，接经验候选、审核与能力发布；用多个独立小工作验证真实复用，不能把同一任务重启计作多次成功。
4. 完善 OpenRig 领取/终态、并发资源协调，再做多小时有界运行观察；常驻服务不作为无人值守验收证据。

每批用少量虚构资料和小任务验证，开发回归优先直接测试代码和接口；关键用户路径再验证浏览器。真实调用沿用已批准预算，交付物必须由员工生成。扩展时保留历史数据和未知费用，不在当前环境做破坏性恢复实验。当前沙箱为每个运行共享，并非每位员工独立容器；清理旧发布必须保护新发布仍引用的固定依赖目录。

闭环详细规则见 [工作、复用与能力沉淀](knowledge-learning-loop.md)。桌面扩展、手机端、新图数据库和无约束自进化暂不进入本阶段。
