## 打开或启动

工作台地址为 [http://127.0.0.1:4310/](http://127.0.0.1:4310/)。已有服务运行时直接打开页面；升级或更换启动方式前先停止旧服务，不要同时启动两份服务。网页可查看、预览、下载交付和真实测试输出；重启不会自动恢复已停止的付费项目。

推荐双击项目根目录的 **`start-local-production.cmd`**。它检查 Node/npm 和项目、员工运行器两侧依赖，先执行类型检查与网页构建，成功才启动生产静态网页。缺依赖时窗口会给出对应安装命令；构建失败保留真实错误码，不会启动服务。保留这个窗口，使用 Ctrl+C 停止。构建不调用模型，启动后是否付费仍由网页操作、预算及审批规则决定。

另一台电脑首次安装时，需要 Node.js `^22.19.0 || >=24`（22.x 至少 22.19，或 24 及以后），并包含 npm。在项目根目录打开 PowerShell：

```powershell
npm ci
npm --prefix services/agent-runtime ci
.\start-local-production.cmd
```

默认使用**这份源码目录下**的 `.data/local`；新目录是独立环境，不会自动读取其他副本的配置。沿用已有环境时，把完整本机数据目录作为参数传入：`start-local-production.cmd "--data-dir=已有目录的绝对路径"`。目录内数据库、凭据、工作区和设备授权继续保留，无需复制密钥或重新授权。启动锁拒绝同一目录的第二个服务；网页端口占用且需要独立环境时可加 `--web-port=4312`。

也可先 `npm run build`，确认成功后运行 `node scripts/local.mjs --production`，附加同样的目录或端口参数。生产模式使用 `dist/web`，不加载 Vite 或开发热更新；修改源码后需重新构建并重启才生效。原 `start-local.cmd` 与 `npm run local` 保留开发模式。`npm run local:check` 只验证隔离的本机 API 与执行器，不能代替静态网页验证，也不能与 `--production` 混用。

## 从需求到交付

2026-10-05 续报：网页已增加“检查恢复条件”，只读核对费用、调用次数、授权、检查点和未知操作；改变费用确认选项需重新检查，提交仍再次核对。它明确不保证具体模型请求或整条执行链可付。当前新恢复的零费用原生预检在完整四文件阶段仍受预算阻断，详见[具体请求证据](validation/fresh-recovery-native-preflight-2026-10-05.md)。服务仍运行，但原 v6 项目没有自动付费续跑。

1. **检查模型。** 新环境进入“模型目录”，填写中转站 API 前缀、Key、模型和单价，再分别测试连接与工具能力。当前配置为 `https://opencode.ai/zen/go/v1`、模型 `deepseek-v4.1-flash`，接口协议选 **Chat Completions**，思考模式选 **关闭 thinking**；保守单价按每百万 Token 输入 **$0.30**、输出 **$1.20** 填写，实际供应方计费以其后台为准。已有环境可直接选择 **Go · DeepSeek V4.1 Flash**，规划、开发、QA 和经理都可使用它。模型测试、需求对话及执行均按中转站计费；保存配置不自动调用模型。GLM 5.2 的当前试调用返回 400，先不要选为员工路线；具体拒绝原因仍未确认。New API 裸站点地址会补齐 `/v1`，公开价格按站点分组与倍率导入；未公开的价格不猜测。
2. **持续讨论。** 首页描述需求，回答追问，继续补充或修改人员与任务。页面分别显示“尚未生成团队方案”“本轮方案未生成成功”和待确认团队方案。失败或有未发送修改时，先继续生成有效新草案；“继续获取回复”用于取回结果不明的原请求。
3. **确认组队。** 检查完整任务草案，点击“确认组建团队”。只有此时保存部门、员工和项目。后续调整须重新生成方案并点击“确认更新团队”，运行前再检查项目。
4. **检查并批准。** 项目中检查模型、工具、依赖、输入来源、输出文件、验收标准与预算。输入/输出 Token 是整项任务的多轮累计估算；新方案可由 AI 单列“单次最大输出 Token”，旧方案可保留空值。预算校验扣除已用费用与尚未确认的预留。验证命令填写精确可执行命令，例如 `node --test todo.test.mjs`；允许写入范围逐行填写实际相对路径，不能把说明文字或模糊目录范围当作文件授权。完成校验后批准运行。
5. **逐次审批。** 执行页显示当前节点、员工状态、累计费用及“任务、交付物与审批”。阅读命令和参数后点击“批准这次操作”；拒绝或停用后不会直接执行。文件、代码和报告由员工生成，用户不需要替员工补写交付。
6. **验收与下载。** 查看各节点完成记录、独立审查结论及“本机操作回执”的真实退出码和输出。交付物可预览和下载；“导出完整追溯”保留 Run ID、调用与审批记录。按员工生成的 README 启动和测试项目。命令通过但任务交接或经理验收未完成时，项目仍未完成。

已存在项目需要 AI 修改时，在“项目与方案”选择规划模型，点击 **“检查规划费用”**。检查不调用模型；费用足够后才点击 **“生成 AI 候选（会计费）”**，查看完整候选，再确认保存或丢弃。只有确认才替换项目方案；生成失败保留原版本，丢弃不会退回已发生费用。未通过执行校验的候选只能明确保存为草稿。网络结果不明时保留原请求，通过“继续读取同一生成请求”处理，不反复生成。历史来源、已核验节点和文件 SHA 可在检查结果展开；保存新方案不自动继承旧运行检查点。[实际网页与 API 验证](validation/project-planning-candidate-stage-2026-10-05.md)。

预算由方案 AI 估算整项任务的累计模型用量，并可分配任务上限；用户确认项目总上限，执行程序据真实费用与未知预留守住上限。员工每步能看到当前净余额、任务已花费用和剩余次数，据此节省操作。网页“静态估算”含 20% 余量，仍可能低估多轮执行；不能把它当中转站实收或保证完成的报价。当前反馈修复已验证，但完整动态重规划/阶段额度自动再分配尚未实现。

## 员工上下文与资料

在“项目执行策略 → 员工上下文管理”选择方式；策略保存新版本后需要重新批准：

- **自动摘要与工具结果缩减**：默认方式。填写模型上下文容量后，容量压力可触发真实模型摘要；摘要费用和次数计入原上限。未填写容量时保留工具缩减与请求大小保护，不猜测容量。
- **仅缩减工具结果**：缩短过长日志等结果，不额外调用摘要模型。带路径和 SHA 的完整文件读取保留正文，结构化证据仍保留版本、哈希和状态；被缩短的文字会标记不完整。
- **仅限制请求大小**：关闭上述摘要与工具缩减，发送前仍检查实际请求字节数和可用费用。完整必要上下文放不下时会停止，并显示失败原因；切换方式不会增加预算。

每名员工有自己的会话，按当前任务、输入来源及授权获取资料。当前批准需求与合同、固定文件和知识引用、恢复依据受发送前检查保护；有来源证明且归属、版本、完整内容都相同的重复只读结果才可合并。历史完整记录仍保留，不能把摘要当作新的授权或验收证据。

在启动数据目录下，`runs` 保存运行快照与追溯，`workspaces` 保存员工实际工作文件，`journal` 保存本机操作记录，`obsidian-vault` 保存知识笔记。查看“交付物”和“导出完整追溯”即可取回对应 Run 的资料。恢复以固定版本、文件 SHA、已接受交接和实际操作回执核验；员工可按授权读取自己的完整历史，旧审批不会直接重用。知识库更新不会改变已批准 Run 的引用版本。

## Todo API 示例

首页可输入：

> 请组建经理、开发、独立 QA 共 3 名员工，按 4 个串行任务完成仅用 Node 内置模块的 Todo API：开发生成 server.mjs、todo.test.mjs、README.md；QA 生成 acceptance.test.mjs，启动真实 CLI 子进程并通过 HTTP 独立验证；QA 再审查开发与独立测试，输出文件留空；最后经理完成文字验收。服务只绑定 127.0.0.1，提供 Todo 增删改查及 400/404；README 写明 Windows 启动与测试命令。所有文件由员工生成，命令逐次审批。

确认后在“编辑方案”核对以下合同，必要时在网页修正后保存新版本：

| 节点 | 合同检查 |
| --- | --- |
| 开发 implementation | 输出及写入范围为 `server.mjs`、`todo.test.mjs`、`README.md`；验证 `node --test todo.test.mjs`。 |
| QA verification | 依赖开发；输入三个开发文件，生产任务均指向开发；输出与写入范围仅 `acceptance.test.mjs`；验证 `node --test acceptance.test.mjs`，须实际启动服务并请求 HTTP。 |
| QA review | 依赖开发与 verification；被审查任务指向开发；输入三个开发文件及 `acceptance.test.mjs`，各自生产任务分别指向开发与 verification；输出文件留空，沿用只读独立审查。 |
| 经理验收 | 依赖 QA review；输入四份文件准确绑定开发或 QA；输出和允许写入范围为 `acceptance-report.md`，核查真实测试回执、文件和运行说明后写报告。 |

原示例预算 **$0.48**、最多 **3** 人、并发 **1**、全项目模型调用 **80** 次、时限 **1800** 秒、上下文 **192000** 字节。当前 v6 扣除旧 43 次后上限 **37** 次，每员工每任务 **14** 次，已用 **21 / 37**；历史合计 **64 / 80**。费用与次数恢复时继续累计，沿用原全局/部门限制，不因失败自动扩大额度。工具只授予任务需要的读取、写入与测试能力。

## 中断后恢复

服务重启后先打开原运行，查看停止原因、已完成节点、审批、操作回执与费用状态。已完成的可信节点保留，未完成节点续跑，旧命令审批不会重用。点击“恢复未完成任务”会创建新 Run；“完整重试”会重新执行全部任务。

如提示费用待核对，进入“用量与费用”或“系统设置 → 每日预算与待核对费用”，找到对应 Run 的收据及“手动核对费用”。优先精确比对供应方请求 ID；自动查询只有取得唯一对应的实际账单才结算。相同中转站配置的账单接口明确拒绝或不支持时，自动查询会暂停；修复该接口后可点击“查询中转站账单”，主动重新探测。临时失败或账单延迟仍有最多三次自动查询。任何查询失败都保留待核对费用，不重新发送模型请求。

人工核对依据中转站账单填写完整输入/输出 Token、请求编号或查询时间，勾选已核对账单，再点击“确认记录用量”。只有明确确认没有扣费，才能把两项都填 0。没有对应账单时保持收据未知；若页面显示没有在途调用、没有未知本机操作且仍有净可用预算，可以勾选 **“保留未知费用预留，在原预算继续”**，再批准或恢复。页面分别显示已登记费用、未知预留及可用余额；没有勾选时仍阻止继续，选项不会替收据结算。人工结算一条收据不代表账单接口权限已修复，不能将其零费用结果套用到另一条请求。

本地金额按已配置输入/输出单价登记；供应方缓存折扣可能使实收更低。仍填写完整输入总 Token，不把缓存折算数冒充实际 Token。费用页面保留未结算预留，不把 Key 的授权上限或累计额度点当作可用余额。保留未知预留不保证余下单次请求可付：`BUDGET_CONTEXT_LIMIT` 会在发请求前阻止无法在原净额容纳的完整合同/证据；字节配置不足则显示 `CONTEXT_LIMIT`。不要因看到正余额就反复重试同一失败步骤。

若出现结果未知的文件修改或命令，先检查操作详情与现有文件，确认实际影响后才勾选核对确认。系统不会盲目重放。档案损坏、版本变化、知识授权失效或额度耗尽的具体原因会阻止恢复，应先处理页面提示。

## 独立测试发现开发缺陷时

恢复和完整重试沿用原批准范围，不能授权 QA 修改已完成的开发文件。若方案没有授权自动返工，通过网页修订：

1. 在旧 Run 下载员工原文件。进入“文件与项目导入”，用“选择文件”导入需要保留的文件，保存独立快照；选择整个目录会保留顶级目录前缀。
2. 原项目“编辑方案”选该快照，勾选文件和“复制文本文件到独立运行工作区”，给本来具有文件/终端权限的项目员工逐个授权。
3. 在素材文件下展开完整 SHA，复制到对应“已固定版本的工作区文件”输入。开发仅修复自己的输出，QA 仅修改独立测试；下游输入绑定新生产任务，不固定旧开发输出哈希。
4. 把已确认的问题、真实复验命令和验收标准写入目标，保存新版本并批准。项目预算包括之前支出，不提高原额度；新方案的调用限额须扣除之前已用次数。文件由员工修复。

未完成节点若已修改其固定输入，恢复会拒绝原哈希不匹配。安排中断验证时，应停在已完成开发、QA 尚未修改其固定输入、无在途调用/操作的审批点；正常用户不需为验收故意中断。
