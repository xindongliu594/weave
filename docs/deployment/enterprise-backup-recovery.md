# 完整企业备份与隔离恢复

当前 v2 已完成 Windows 隔离数据库、进程中断、HTTP、网页导入及本地受信 TLS/OIDC 协议验证。原生 PostgreSQL 多连接和跨引擎恢复、真实公司 IdP、JJ 本轮发布仍未验证。先在新实例演练，不直接替换当前环境。实际结果见[验收报告](../validation/enterprise-backup-preserving-restore-2026-10-29.md)。

## 备份包含什么

v2 保存固定的 44 张业务及企业历史表，以及受管理的交付/追溯/检查点文件、活动知识笔记、密封凭据所需主密钥和已登记的原生插件包。保留未知费用、未确认操作、知识版本、审计及审批历史。它不复制旧登录会话、有效设备令牌或运行中的设备进程，也不是整机镜像；未登记的工作目录、完整 Obsidian 回收站和 OpenShell 运行环境不在此在线包范围内。

明文包上限 50 MiB，加密请求上限 70 MiB。超过上限会拒绝，不能删历史来强行通过。旧 v1 是业务备份格式，不能代替完整企业恢复；不要将 v2 文件交给 v1 接口。

## 通过网页导出

1. 原环境管理员登录后打开“设置”的完整企业备份区域。
2. 输入 12～200 字符的备份密码，点击“生成并下载完整企业备份”。
3. 保存下载的 JSON 和密码，并妥善保管。密码遗失不能通过重置登录密码解密；包内含敏感历史和密封凭据材料，不上传公共仓库。

正在执行或排队的项目、模型调用和经理消息会阻止导出。等待经理回复结束，或在原对话页明确“取消等待”后再备份；不会为了备份自动取消消息。`replied`、`failed`、`cancelled` 历史仍可保留。旧包若含等待或回复中的经理消息，导入也会拒绝，避免激活目标后自动调用模型。

导出遇到未确认状态时保留原记录，按错误提示核对。不要取消未知费用或修改历史以绕过导出保护。

## 准备全新目标

恢复只支持全新隔离实例，不合并、不覆盖已有企业数据。目标使用兼容代码版本、独立的空数据库及全新的 `DATA_DIR`、`TRACE_ROOT`、`OBSIDIAN_VAULT`；绝不能指向原环境的路径或数据库。原环境保留到验收通过以后。

由部署人员使用现有 API 启动入口 `apps/api/src/index.ts` 和网页配置准备目标，先以 `WEIWU_AUTH_MODE=legacy-local`、回环监听提供仅本机可见的导入页面，不暴露匿名公网入口。无需手工修改数据表。不要先创建部门、用户、设备或插件来“初始化”目标，正常迁移产生的默认空结构由导入器识别。

`npm run local` 是日常单人启动器，会自动登记本机执行设备，不能当作企业全新恢复目标的准备步骤。已有 OIDC 初始化或设备记录的目标也会被拒绝；应重新准备独立空实例，不清表伪造空目标。

## 导入、重新登录与激活

1. 在目标设置页展开“导入到全新隔离实例”，选择备份 JSON，输入密码，点击“预览并核对备份”。核对表数、文件数、未知费用和未确认工具效果数量。
2. 输入 `RESTORE ENTERPRISE`，点击“确认导入备份”。服务端重新验证密码、包、目标及文件，不以预览结果代替实际检查。
3. 成功导入后显示“执行保持隔离”和恢复编号。记录该编号；此时不会自动续跑。点击“重新核对恢复状态”，确认物理文件核对通过。本机 owner 不能点击激活来恢复执行权限。
4. 部署人员按[企业身份配置说明](enterprise-identity.md)配置目标的受信 HTTPS、同一 OIDC issuer、原引导账号的精确 issuer/subject 和目标会话秘密，然后重启 API。IdP 须登记目标的精确回调 URL。导入过已激活企业历史的实例若继续以 `legacy-local` 重启，会拒绝启动，这是身份保护。
5. 原来仍有效的管理员在目标重新登录，再回到设置页核对并点击“核对后激活执行”。旧 Cookie 不恢复管理权限，改用另一个引导账号也不能接管历史。
6. 激活只解除环境总隔离。分别核对并重新授权设备/目录、插件、MCP、工具合同和自动化配置，检查项目当前权限、预算和未确认操作，再继续项目。不能直接重用旧设备令牌或盲目重放结果未知的操作。

当前首版要求原身份服务及有效管理员可用。跨 issuer 迁移、所有管理员失联后的接管没有实现，不提供临时升权入口。

## 中断或提示异常时

- 请求断开或页面刷新后，先用原目标的“重新核对恢复状态”读取恢复编号与状态，不连续重发导入。
- 若为待核对状态或 `BACKUP_RESTORE_RECONCILIATION_REQUIRED`，保留目标、恢复 manifest、回执及两侧文件。写入屏障会保持；不要删 `active.json` 或隔离标记来强行启动。
- 如果提示目标非空，不在该目标重试覆盖。核对是否选错环境；需要重新演练时另建空目标，原目标留作检查。
- 物理核对失败时保持隔离，不激活。备份恢复成功也不代表交付业务验收通过，应另行验证交付文件、项目测试结果及恢复后的授权范围。

本页是操作说明，不代替原生数据库、实际公司身份接入和部署验收。
