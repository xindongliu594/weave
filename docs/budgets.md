# 执行预算与调用次数

创建项目或从需求组建部门时，可设置方案总调用次数和“每员工每任务调用上限”（默认 40 次）。编辑任务时可以单独填写费用上限和更低的调用次数上限。未填写任务费用时共享项目剩余额度；填写后同时受任务和项目两层限制。任务估算含 20% 预留，不能超过填写的任务上限。

Runtime 在发起 HTTP 请求前同时预留项目和任务费用，预留计算包括消息、工具定义及最大输出。并发员工不能重复使用同一份额度。每次实际请求计一次调用，包括 429/503 后尝试备用模型；本地校验拦截的请求不计次。经理协调会话计入项目，执行成员会话按 AgentTeams 状态归属任务。

费用累计达到 70% 时提醒；90% 时不再自动切换备用模型，并禁止通过恢复/完整重试增加调用；100% 时不启动新请求。新建员工和任务始终受批准方案约束。已在途调用仍可能返回，真实用量会先持久化；供应方返回的实际用量超过保守预留并导致预算超额时，停止继续执行该响应中的工具。预留是本地估算，不是供应方的费用封顶承诺。

同一方案版本的重试继承先前全部尝试的调用次数，以及每任务已记录的费用。重试不会清零额度，耗尽时要求用户编辑方案后重新批准。新方案版本可重设任务额度，但项目总费用仍包含之前的规划和执行费用。历史档案缺失或损坏时不允许按零次计算。取消且从未启动的排队任务不占模型调用额度。

任务归属来自固定版本 AgentTeams 的 `team.json` 运行状态（只读），与成员会话、员工和已批准任务映射交叉核对；不会把需求或消息中的 `Task:` 文本当成扣费依据。该状态位于宿主机运行目录，员工的 Docker 文件工具无法修改。DSH/AgentTeams 升级需要重新验证状态结构与任务分派测试。

执行记录保留 `budget/warning`、`budget/stopped` 和每次 `model/wire-request` 的任务归属。网页显示阈值与停止原因。旧运行没有本次新增的预算机制标记，界面不会把新策略显示为其历史执行事实；可追溯的旧模型请求会计入恢复时的总次数。

全局每日预算和可选的部门每日预算按 UTC 自然日统计，覆盖规划、连接测试和正式运行。批准运行时预留剩余执行预算；运行内部的请求不会重复计入每日预留。规划和连接测试在发送前单独预留，数据库串行校验防止并发调用重复占用额度。部门预算留空时仅受全局上限约束，填 0 时不能新增收费调用。调整限制影响后续批准和请求，不撤销已经发出的请求。

每次请求在数据库中保存独立编号、批准的模型单价、项目/运行/员工/任务归属和状态。收到有效用量后结算，即使响应正文格式错误也记录费用；未发送的请求释放预留。断线、无用量响应、HTTP 错误或请求租约过期后，状态改为待核对，继续保留额度，跨日也不会自动清零。项目存在未结算请求时不能重新规划或重试。429/503 的备用请求使用新编号，原请求仍保留待核对费用。

“系统设置 → 每日预算与待核对费用”显示已确认费用、预留和部门限制。用户依据中转站账单填写输入/输出 Token、核对依据并明确确认后，按请求时固定的单价结算。仅确认没有扣费时才能填两个 0。系统保存人工核对历史；迟到的有效供应方回执会更正同一条用量，而不是重复收费。当前费率模型按输入/输出 Token 计算，未单独支持缓存、图片或其他供应方计价项目；显示金额是配置费率的计算结果，不能冒充供应方账单。

备份和恢复拒绝进行中的模型调用。待核对费用及核对历史包含在加密备份中，恢复后仍占用额度。旧版备份缺少预留表时保持兼容，但升级前未收到用量的调用无法追溯重建准确费用，不会编造历史预留。
