# 项目策略与执行授权

项目的“允许范围”和员工的具体配置分开保存。策略包含允许使用的模型（规划、主模型及备用模型）、工具、知识空间，以及预算、人数、并发、调用次数和时限。

新项目默认继承创建时员工实际配置中的模型、工具和知识空间；空列表表示不允许使用，不代表无限制。部门后来新增权限不会自动扩大已有项目。既有项目升级时也只从当前方案继承缺失的允许范围。

在“项目与方案 → 编辑方案”中调整项目执行策略，再为员工选择具体模型、工具和知识库。策略允许某个空间不代表每位员工都能访问：公司、部门和员工私有空间的归属检查仍然生效。人工编辑若超出策略会被拒绝，需同时明确调整策略。组织草案保存前也可编辑这些允许范围。

规划模型必须在允许列表内，发起请求前检查；提供给规划器的模型目录也限于该列表。返回方案不能选择范围外的主模型或备用模型。员工工具和知识权限仍按原员工配置收窄，新员工不会因为规划器生成的文本自动获得工具或知识权限。用户选定的本次资料及接收人不会被规划器替换。

每次修改方案或策略保存为新版本，版本下载包含当时策略。旧版系统没有保存的历史策略显示为未知，不用当前策略补写。运行批准时固定策略和员工配置；项目排队或运行中不能修改方案，需先取消并等待停止，再保存新版本、重新批准。历史内容始终可查阅。

重试和检查点恢复只允许当前方案版本；部门已归档、知识空间已归档或员工已失去该空间访问资格时拒绝恢复。恢复沿用原来的资料版本，不将新笔记补入旧快照。模型配置变化时仍需重新批准，见 [模型能力验证](model-capabilities.md)。运行启动和新的模型请求也会重新检查授权。

工作进程在数据库费用准入事务中再次检查租约所有者和有效期，防止排队等待期间已经失去租约的旧进程继续发起请求。项目编辑、队列领取、取消和恢复使用相同的项目、运行锁顺序；竞争恢复最多创建一个后继运行。关闭中的工作进程不再领取或启动新任务。

允许范围、方案策略版本和批准快照进入加密备份。旧备份缺少允许范围时按当时保存的项目方案继承，历史策略仍保留未知状态。
