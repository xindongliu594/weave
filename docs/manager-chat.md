# 从需求组建部门与经理持续对话

当前实现中，首页需求对话与项目经理咨询由网页 API 通过 `completeBudgeted` 调用配置的模型；尚未接入 DSH 原生会话组件。批准后的员工执行由 `ProductDshRuntime` 使用 DSH + AgentTeams 承载。部门、员工、方案确认、持久化和费用控制是为伍的业务层。

## 首页：从需求组建部门

在首页与为伍持续讨论想完成的事，选择连接测试通过的模型，并确认人数、预算和允许提出的基础工具。先聊目标、岗位与职责，不要求每轮都生成完整任务；需要形成或修改团队时，再返回可编辑方案供用户确认。参考模板提供岗位示例，不要求照搬人数或名称。对于“成为另一个我、7×24 小时工作”这样的目标，会进一步明确事务范围、预算和监督条件，不保证无条件持续运行。

默认请求未指定 `allowedTools` 时不授予任何工具，只能产生需求/文字规划任务。页面可显式选择工作区读取、交付物写入和测试终端；模型只能给员工分配选中的工具。代码实现草案需要文件范围、输入输出、实际验证命令及另一位员工的独立审查；自动返工、知识空间、浏览器/MCP、其他部门身份和备用模型不能由此次对话自行授予。

发送和生成预览都不会创建部门、项目或执行任务。检查右侧草案并保存后，才创建部门与 `DRAFT` 项目；之后仍需模型工具能力验证、方案检查和项目批准，终端命令逐次确认。项目需求由用户消息按顺序汇总，助手的陈述不会被当作用户需求写入。

点击“确认组建团队”后，部门及员工持久保存到“部门与员工”，页面保留聊天输入。可以继续咨询或修改，新的有效方案通过“确认更新团队”更新同一部门和草案项目，避免重复创建。更新请求附 `target:{departmentId,projectId,departmentVersion,projectVersion}`，服务端同时检查两个版本，原子保存员工与任务方案，并保留配置历史；岗位职责变化会递增岗位版本。项目已进入执行、团队正在参与其他运行、版本已变化或还有待结算费用时拒绝覆盖，原数据保持不变。

当前标签页的对话、输入和草案保存在 `sessionStorage`，页面导航及刷新后可恢复。发送前同步保存请求正文与幂等键；网络响应丢失时，可继续获取原请求结果，恢复期间不能重复提交新消息。清空预算等临时无效输入不会覆盖已保存的有效草稿。普通文字讨论不会修改已生成方案；只有通过校验的新候选才更新方案。候选不完整或超出当前授权时保留回复与上一份方案，提示继续修改，不把未通过的新要求当成已合入。

每次咨询经过费用预留和每日预算检查，默认本轮费用上限 $0.10，也不超过请求里的预算额度。生成并采用某份草案的**本轮**费用在保存时归入项目；后续确认更新时，历次已采用方案的规划费用累计计入项目预算。前面的追问、未采用的旧草案和失败轮次独立记入全局用量，不计入最终项目预算。因此项目预算不是整段需求咨询的累计费用上限。原先不调用模型的模板预览入口继续保留。

接口：`POST /api/organizations/chat` 接受 `{messages,modelId,policy,templateId?,maxPlanningCost?,previousPreviewId?}`；`messages` 仅允许 `user/assistant`，末条必须是用户消息，每条最多 6,000 字符，无固定轮数上限。完整请求正文合计最多 200,000 字符，用户消息原文及分隔符合计最多 50,000 字符，与项目保存容量一致。前端保留完整历史；模型上下文只包含最近最多 20 条且不超过 24,000 字符的消息，并补充较早用户需求最多 8,000 字符的摘录。较长摘录明确标记中段省略；最终项目需求保留全部用户原文，不用摘录替代，也不包含助手发言。

返回 `{reply,preview?,draftIssue?:{code,message}}`。自然语言、有效 `reply`、单个 fenced JSON 与 `candidate:null` 都可正常对话；候选结构、权限或计划校验失败返回非阻塞的 `draftIssue`，不创建新预览。被截断的 JSON 仅在开头含完整 `reply` 字符串时保留该回复，其余情况返回固定的可继续提示，绝不直接显示 JSON 碎片。预算、模型和请求输入错误仍在调用前拒绝；模型已产生的费用正常留存，解析失败不会自动付费重试。

有效预览沿用原有结构，可通过 `POST /api/organizations` 保存。继续修订时传入 `previousPreviewId`，服务端向模型提供原员工 ID、任务及依赖作为编辑资料；旧草案不被覆盖，也不会沿用旧权限，本次显式策略仍决定可用范围。原方案资料超过 32,000 字符时只提供员工与任务标识等有限参考，并明确详细职责、合同与依赖缺失，不能宣称完成保真修订。不存在的草案在模型调用前拒绝。重复保存同一预览复用现有部门/项目；同一请求幂等键不会重复调用模型。

## 项目详情：与经理持续对话

打开项目详情的“与经理对话”，输入需求或进度问题，并设置本次回复的费用上限。发送后使用该项目经理配置的真实模型；没有额外执行工具，不会直接修改方案、批准项目、运行命令或发布内容。要采用建议，需要另行编辑保存方案并批准。

消息与回复持久保存到当前项目，页面显示最近 100 条；模型上下文包含最近 12 轮已回复对话、项目方案和最新运行状态。输入最多 6,000 字符，回复有 1,200 Token 输出限制；历史条目和项目资料有上下文截断上限。本次回复费用上限默认 $0.02，仍受项目剩余预算、全局和部门每日预算及未知费用核对机制限制。

项目存在排队或运行中的任务时，消息保持等待状态，结束后才回复。同一项目只允许一条等待或回复中的消息，可以取消尚未开始的等待。消息冻结项目、模型与中转配置版本；等待期间发生变化则拒绝调用，要求核对后重新发送。

失败请求不会自动重发。请求缺失用量或结果未知时，费用预留保留为待核对；返回了用量但没有有效回复时也保留已结算费用。进程退出时正在回复的消息超过十分钟会标记失败，提示检查费用，再由用户决定重新发送。恢复备份时，待回复消息被取消，已回复历史保留。

## 接口与验证

- `GET /api/projects/:id/messages`：对话历史。
- `POST /api/projects/:id/messages`：`{version,content,maxCost?}`，返回待回复记录。
- `DELETE /api/projects/:id/messages/:messageId`：取消等待。
- `ManagerChatService` 约每三秒检查队列，应用关闭时等待当前工作停止。

`npm run test:integration -- tests/manager-chat.test.ts`：6 项通过，使用本地 HTTP 固定模型检查跨服务实例的多轮历史、活动任务等待、重复排队与取消、项目及模型/中转版本变更、权限及预算拒绝、用量持久化、失败不重放和回复中断恢复。没有付费模型调用；不代表真实模型的咨询质量已完成评测。

`npm run test:integration -- tests/organization-chat.test.ts`：首页组建接口的固定模型验证，覆盖澄清不建部门、不启动运行，自然语言/fenced JSON/null/部分候选与截断内容，完整草案及多轮上下文，超过十轮的上下文界限与全部用户需求保存，原草案员工与任务修订上下文，显式工具与模型白名单、隐藏权限拒绝，代码实现与独立审查合同，预算/输入限制，预览失败不改旧草案、费用留存及幂等保存。
