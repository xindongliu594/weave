# 执行追溯首版

2026-09-20。独立 DSH Host 的采集与网页查询已接入正式项目 Run。自动化测试使用本地协议模型；具体用户中转站仍需单独进行真实工具调用验收。

## 使用

启动 `npm run dev`，打开 `http://127.0.0.1:4310/#run`，点击“运行追溯验证”。它会运行真实 DSH + AgentTeams 的两位成员依赖任务，模型回复采用确定性 fixture，不读取中转站凭证、不调用外部模型。生成的运行档案留在本机，可重复打开。

左侧选择员工，可分别查看岗位提示词快照和本次任务提示词。时间线可按模型、工具、团队、会话事件筛选。展开模型请求可查看实际组装的消息、工具定义和模型路由。页面地址包含 Run ID，刷新后仍打开同一运行。

## 存储和采集

业务部门、方案仍在 PostgreSQL。本次运行原始档案保存在 `.data/runs/<run-id>/`，可以通过 `TRACE_ROOT` 更换位置：

- `snapshot.json`：首次创建时独占写入，保存需求、方案版本、岗位与任务提示词、模板版本、启动来源。后续事件不覆盖此文件。
- `events.jsonl`：同步追加并 fsync 的有序事件。以 Session ID + 格式版本 + 源事件序号去重；序号或末尾行异常会标记记录不完整，不显示成功。
- `sessions/`：DSH 的 JSONL 持久会话，用于 DSH 恢复。
- `workspace/.agent-teams/`：插件拥有的团队状态，产品不直接修改。

采集点是 `session/created`、`session/event`、`agent/created`、`llm/stream`、`tools/pre-execute` 和 `tools/result`。程序化工具调用也经过正式工具执行流水线，补充记录到运行档案。插件自定义 session 事件在当前 DSH 不受支持，因此团队工具操作及正式 status 查询快照单独记录。自动调度的任务和 attempt 还可由实际分配消息、claim 结果追踪。

业务事件与底层会话事件有不同来源，时间线保留两者；源会话重放通过 sourceKey 去重。每个档案只由一个 Host 写入。重新挂载会话时会补采该会话已有事件；这不代表已实现全盘自动扫描和中断运行恢复。

## 验证证据

- `npm run runtime:test`：真实团队依赖调度、成员消息、岗位与任务进入实际请求、新进程读取相同历史、修改输入配置不改变历史、sourceKey 去重、残缺日志识别、已知凭证字段脱敏、Host 关闭取消。
- `npm test`：API 创建验证运行、读取详情、重建服务后的同档案读取、游标查询，以及既有业务校验。
- `npm run build`：TypeScript 与生产前端构建。
- 网页提供员工筛选、事件分类、展开详情、历史列表和无 API 验证入口。

## 边界

fixture 运行有明确标签，不能被视为真实模型的交付验收。正式 Run 通过用户中转站调用并要求标准用量，当前只开放团队协调工具；文件交付、终端权限和进程重启恢复尚未接入。

运行快照与事件包含基础敏感字段/Bearer/sk-key 脱敏；不是任意文本的通用机密识别器。DSH 自己的本地会话日志遵循其原始持久化机制，不能把产品归档的脱敏理解为所有磁盘副本都已脱敏。未挂载对外遥测导出。

快照摘要用于发现意外改写；没有宣称防篡改、跨进程并发写入、远程审计存证或断电零丢失。没有结束事件的运行标为“未结束 / 可能中断”，不推测为成功。日志规模增大后，需要增加索引和后台分页读取；当前 API 对已读档案的响应按 300 条事件分页。
