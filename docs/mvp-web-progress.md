## 已修复

- 有效团队草案后，用户补充新要求，模型只自然追问而未生成新草案时，旧实现清空输入并重新解锁确认，可能将未纳入新要求的旧方案保存。现保留旧方案、明确标记本轮讨论未形成新方案并锁定确认；只有新 `preview` 可解除。用户可继续补充或直接点击发送整理新方案。
- 首页区分「尚未生成团队方案」「本轮方案未生成成功」「待确认／已保存方案」；成功自然回复会清除之前的失败提示，仍保留待整理状态。
- 运行页显示项目累计费用、预算、剩余额度、本次运行费用和启动前已用费用。计算为 `max(0, policy.maxBudget - executionBudget) + 本次 billing/usage`；启动前费用含方案规划与此前执行。说明按配置单价与已记录用量计算，以中转站账单为准。历史缺少执行预算证据时只展示已知本次费用，没有推算未知累计值；未用用量记录条数冒充调用次数。
- DAG 使用中文状态、员工名字和前置任务名字；突出当前执行节点、待审批数量及审批员工、工具名称。
- 切换运行 ID 时重建 `RunExtras`，防止新运行短暂显示上一次运行的交付物、审批、引用或预览。读取交付物列表失败现在明确显示错误。
- 真实模型方案将说明文字写入修改范围，导致运行 `a79b1893` 的员工合法输出被 `OUT_OF_SCOPE` 拦截。主任务负责提前校验与模型提示修复；网页现让 `verification` 等任何已有范围或交付文件的任务显示范围编辑，用户能直接修正路径。实现／修复范围仍必填，其余类型为可选；打开编辑器不会自动放宽或改写范围。
