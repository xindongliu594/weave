# 为伍企业落地基础设计

状态：已获用户授权推进；实现及验证以分项证据为准。基线 `4fc7639`。本设计不把现有 MVP 或一次成功运行等同于企业级完成。

## 目标与边界

把现有为伍加固为可在 JJ 部署、由企业内部多人使用的 Agent 工作平台：任务有责任人、执行有隔离、动作可核对、异常能恢复、产物可验收、数据可维护。先交付单组织部署；多租户 SaaS、Kubernetes、跨地域高可用不是本轮默认建设范围。

本轮十项基础能力全部进入交付范围；分阶段交付不意味着删减剩余目标。大语言模型推理继续走已有 API。保留历史项目、用户数据、模型凭据与未知费用。真实付费验收沿用现有授权，不能用新增功能授权替代金额和次数授权。

## 复用决策

1. 身份使用 `openid-client` 的 OIDC/OAuth 协议能力，Express 服务端会话与 PostgreSQL 会话存储。已有 DSH authorization 是插件凭据接口，不能冒充真人认证。企业模式缺少配置时必须拒绝启动，不能退回匿名管理员。保留明确标识的本机单用户兼容模式。
2. 执行继续使用固定 OpenShell 0.1.2。每个 task attempt 的执行沙箱不挂载 canonical 项目目录。已有原生插件私有副本流程可借鉴；仅切换 cwd 或执行后哈希检查不能充当隔离。DSH `ctx.tools.guard` 负责注册工具的授权入口，DSH checkpoint barrier 与为伍持久档案连接。
3. 保留已有 PostgreSQL 协调器、事务锁和 fencing。系统唤醒/维护优先复用 systemd；不会为了“企业级”立即替换成 Temporal 或自建第二套调度引擎。
4. 评测选用隔离安装的 Promptfoo，提供为伍 provider 和证据断言；它只能经已有预算/收据入口调用真实模型。生产观测复用 OpenTelemetry 协议及现有 durable trace。固定 DSH 的 OTel 插件仅反馈模式，不能偷偷打开持续会话上传。暂不在 JJ 强制部署完整 Langfuse 服务群。
5. 知识、Skill、MCP 和插件继续进入同一 DSH 能力发现/授权链路。自行补充业务权限、生命周期、审核证据与网页连接，不另建执行引擎。

研究来源及固定版本核对见 `docs/research/enterprise-identity-2026-10-20.md`、`enterprise-execution-boundaries-2026-10-20.md`、`enterprise-quality-operations-2026-10-20.md`。

## 不可破坏的合同

- 服务部署仍在 JJ；不在 JJ 加载大型语言模型。
- 新企业模式默认拒绝未知路由、未知角色与未声明资源；机器执行凭据与真人会话不同，不能互相替代。
- 身份鉴权和资源授权发生在幂等响应缓存之前；幂等键按主体隔离。
- 权限收回即时影响新的读取、工具调用和恢复；历史授权快照仅用于审计，不能恢复已吊销权限。
- 既有项目目录是可信成果区，不交给员工命令可写挂载。CAS 合并验证基线版本，冲突不会静默覆盖。
- Checkpoint 不回滚已发生的外部效果、账本、审批或审计。结果未知的有副作用操作必须核对，不能自动重放。
- 归档清理只操作本应用可证明拥有的目录；活动运行、未决操作、保留要求及恢复所需版本不可删除。
- 受影响的权限、账本、迁移、恢复变更必须有负面测试和集成验证；固定模型响应只能证明程序路径，不能冒充真实模型验收。
- 每项进度分别标注：未开始、实现中、本地已验证、JJ 已验证、真实业务已验证、受阻；只有所需证据齐全才能完成。

## 发布条件

先在隔离环境验证，再发布 JJ。身份配置迁移、沙箱隔离与数据变更需可回滚；不得让当前用户因未配置 IdP 意外失去旧本机工作台。企业部署只在对应全部安全门禁通过后启用。最终提供部署/升级/恢复手册、权限矩阵、运行与质量看板、验收证据索引和明确限制。
