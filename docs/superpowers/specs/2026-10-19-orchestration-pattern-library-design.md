# 七类编排模板接入设计

日期：2026-10-19。依据：[调研和采纳结论](../../research/orchestration-patterns-2026-10-19.md)。状态：纳入产品接入设计，尚未实现或上线。用户已明确要求五种以上合理编排；具体阶段细节是本次设计建议。

## 目标与保留项

根据业务需求检索、选择、组合可执行模板，生成具体人员和任务图，讨论确认后交现有 DSH 执行，结果可追溯并供下次选型。七种为 pipeline、parallel、router、orchestrator_workers、review_repair、map_reduce、proposal_review；single 保留作简单任务选项，不计入七种多智能体模板。

不替换现有 Harness、员工宿主、插件注册、工具授权、沙箱、账本或恢复。API 推理、JJ 部署、未知费用保留、每项目授权沿用原规则。一个项目恰好一位经理、最多六位员工（含经理）、最多 50 个批准计划节点、memberMaxDepth=0；合同返工轮数仍为批准值 0～2，新增节点沿用现有费用和调用上限，不自动额外授权。计划任务数、员工数和模型调用数分别限制，不能互相替代。

新模板准入另外核对最坏展开节点数：基础节点数 + 2 × 各自动返工入口批准轮数之和 ≤ 50，因每轮原生返工产生 repair/review 两节点。轮数只计算唯一的合法返工入口。所有可能调用及其费用仍须在整图批准额度内；不能靠“节点尚未生成”漏算。此约束用于新模板，不反向改写旧运行。隔离用例覆盖 46+2×2=50 与 48+2×2=52 的准入差异。

## 模板与运行实例分开

模板记录 id、版本、内容 hash、来源/原格式、适用任务、排除条件、角色槽位、所需能力、输入输出/检查约束、执行语义、验收证据与状态。不保存实际 API Key、生产员工 ID、旧完成结果或凭空估算的提速数字。

实例记录选中模板版本、组合关系、理由、绑定员工及来源部门版本、固定输入清单、最终 Plan/DAG、具体预算与权限。运行恢复使用这个快照，不重新检索 latest 或重新选人。模板归档只影响新推荐，不破坏已有实例。

实例及验收证据同时固定 DSH、AgentTeams、适配层构建版本和相关模型路线版本。`real_verified` 必须声明适用的运行器与合同语义；升级运行器后重新做兼容验证，不能仅凭模板 hash 未变自动继承通过状态。旧实例始终保留原证据，不追溯覆盖。

模式名称属于产品目录，底层只有一份执行图。旧 `orchestration.pattern` 三值及既有运行档案兼容读取；增加 versioned template reference 时须显式迁移 schema，不能只改 enum 后让页面把未知语义当作 pipeline。现有 templates 表只有部门/角色 API，不能把新模板塞进去就宣称有不可变版本；实现前复核现有版本与备份机制，采用最小增量存储。

## 七类执行边界

| 模板 | 必需语义 | 首期限制 |
|---|---|---|
| pipeline | 前置产物完成后交接；末端检查覆盖全部需求 | 沿用现有任务依赖 |
| parallel | 不同专业分支；汇总等待全部必需输入 | 非全部成功不可交付，不用共享文件竞争实现汇总 |
| router | 规划时选择适用流程，封存选择理由和分支 | 只支持执行前路由；未知/歧义不自动执行，不计作运行时条件分支 |
| orchestrator_workers | 按目标动态生成节点、角色与边，再验证确认 | 动态发生在批准前，仍只绑定授权团队，不开放运行中任意 spawn |
| review_repair | 独立审查、具体问题、限定范围修复、再检查 | 仅现有 implementation/repair→review 文件合同，要求范围与实际 verify；不限制文件扩展名，普通 work 循环仍不支持 |
| map_reduce | 同一方法处理固定分片，汇总全量结果并核对覆盖 | 批次在确认前确定；有界展开；工作节点数不等于员工数；不得超过人数/节点/预算限制，每个节点 inputs 沿用最多 40 项 |
| proposal_review | 两位提出者独立准备，同步后各做一次质疑，经理按证据裁定 | 最多两位提出者、每人一次质疑；不无限群聊。不满足独立质量检查的角色组合不准执行 |

组合第一版只有一个主模板与可选的已支持子步骤，每个选择映射到同一扁平 DAG。禁止递归模板调用。组合后必须重新验证全部权限、依赖、单写者和交付覆盖，不能把“各模板单独有效”当作“组合有效”。新输入来源若只能执行后发现，则先完成发现任务、生成下一阶段待确认方案；首期不能静默追加未知数量的分片。

## 复用接口的优先顺序

1. 继续用安装版 AgentTeams 的现有工具暂存任务、批准、调度和原生返工；沿用 Host 的 lockPlan、ReworkGate、Semaphore、员工工具注册与证据校验。
2. 在隔离测试中验证安装版 Profile 的公共插件配置接口；Profile 若只能保留弱化任务字段，不用它替代完整 Plan，仍通过已有 create_task 桥接。team-gui 仅公共 recipe/schema 候选，禁止长期 deep-import 私有内部模块。
3. Cortex 匹配作为对照，不启用其 startTask/模型池/独立账本。先权限与能力过滤，再比较已有检索、简单规则和候选评分；不把相似度当准确概率。
4. LangGraph JS / ADK / AutoGen 用于对照明确的分支、分片、循环与终止语义。无必要不增加它们的执行器依赖；源码复用须固定版本、保留许可与归属。

## 选择、授权与质量

程序先过滤员工能力、权限、运行器支持、输入规模、可承担的费用。AI 在现有规划调用中选择模板、解释分工，缺匹配时提出新草案或说明缺口，不默认强行返回七选一。

用户看到业务步骤、人员、并行部分、验收方法、预算和未满足条件。只有具体 Plan 可执行才能确认；确认时再次验证来源版本和授权。新模式的标签不得隐含执行权限。

每项交付要求须关联产出、之后的检查任务、实际证据。多个 agent 投票通过不能代替事实；多方案评议必须保留分歧与证据，必要时结论是“不足以决策”。测试/程序检查能验证的内容优先验证实际产物。作者与需要独立检查的检查者不同；经理等待检查后交付。

上下文按任务和产物版本传递，不广播全部聊天。并行各写不同产物，由汇总者单独写最终文件；修订继承原始目标，不删除失败项。所有分片、评议和修复调用都计入既有账本；暂停、重启及未知外部操作仍走既有保护。

现有返工恢复的支持边界是独立复验已通过的检查点；半完成 repair/review 目前拒绝恢复，必须保留产物并显示重新批准/处理入口，不能自动重放。支持任意返工中间点恢复另作扩展，不是本次模板定义能补齐的能力。跨部门人员按现有授权展平进入同一 team，不因此增加递归层级。

## 实施阶段与通过条件

### 阶段一：复用探针与目录

- 不付费验证安装版 Profile 的暂存/批准隔离，拒绝无完整合同、运行中改图和越权人员；无法保留产品合同则使用现有桥接，记录原因。
- 建七类不可变定义和证据状态，保留 single。状态至少区分 planned、offline_verified、real_verified；未达到本产品门槛不能进入自动执行候选集。
- 旧方案/旧运行不增加新默认字段、不改变历史费用、验收标准与恢复行为。

### 阶段二：规划和模板实例化

- 新增契约模块与有限实例化逻辑，复用现有组织目录、计划验证与确认；程序仅处理稳定 ID/结构，业务分工仍由模型提出并接受验证。
- 40 条离线任务：七类各四条共 28 条；另十二条为缺权限、缺输入、歧义、无匹配、超人数、超节点、文件冲突、循环、检查缺失、源版本变化、撤销授权、模板归档。标签允许多个合理模式。
- 记录匹配正确率、有效方案率、误执行/越权次数、延迟和输入输出大小；离线安全/结构用例必须全部通过，越权与错误放行必须为 0。模型选择质量另作真实评估，不用桩响应证明其准确性。

### 阶段三：执行、网页和恢复

- 顺序/并行验证依赖与末端门槛；分片验证漏片/重片/失败分片；评议验证独立初始上下文、固定轮数、证据裁决；代码返工验证 0/1/2 轮和额度耗尽。
- 规划时 router/主管拆分的选择及最终 DAG 必须一起封存。选路失败不创建项目；重启不重新选择。
- 网页显示实际流程和可核验状态；planned 模式只能说明用途，不能显示“已支持”。恢复时固定模板与文件版本，完成节点不重跑，恢复入口与费用来源可追溯；半完成返工节点拒绝恢复的反例也必须验证。
- 每个准备开放的模板至少一份真实小任务证据，含真实规划、员工工作、独立检查与经理验收；至少一份并行/分片任务和一份合同返工任务在受支持的独立验收边界验证受控重启。旧 Word 顺序证据仅作基线，不自动覆盖新模板版本。
- 真实任务的项目级金额、调用数和资料权限先核算既有授权，不自动使用剩余累计额度。本次不安排付费调用。

### 阶段四：发布与效果沉淀

- 模板版本关联真实运行、模型、输入规模、命中情况、规划/执行耗时、Token、费用、返工和验收结论。只有可比任务才报告收益，样本不足明确标注。
- 新经验先产生私有候选，经测试与审核才成为可推荐版本；不因使用次数多而自动升级权限或公开发布。

## 不在本轮范围

多层递归团队、运行中自主 handoff、开放式辩论、无限循环、长期事件唤醒机制另立阶段。当前研究没有证明候选插件可直接替换现有生产执行，也没有证明增加模板数量能改善规划成功率。
