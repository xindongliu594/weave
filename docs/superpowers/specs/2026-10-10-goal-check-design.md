# 长任务目标固定与节点检查

用户已批准本轮：目标固定 → 节点检查 → 偏离暂停；先本地故障注入，再网页与小任务验证。复用 DSH AgentTeams、批准任务合同、HandoffGate、ReworkGate、监督器及恢复检查点。不引入新依赖或每回合目标评判模型。

批准执行时，由后端对原需求、方案版本、原任务（含验收、文件、依赖、预算）、员工权限、执行策略和模型配置指纹生成 SHA256 封印，保存在运行快照中。它不来自员工摘要。每次模型与工具准入、正式交接和恢复前校验；异常保留原因并停止新请求，原有请求仍按原账本结算。更改目标需要用户重新制定并批准方案。

每个节点的受保护上下文始终带原目标、版本、原验收条目编号、原文件范围。压缩、知识资料和恢复摘要只是数据，不能替代这一合同。已有正式测试证据及独立 QA/经理验收用于检查实际成果。合法返工可增加来自审查问题的修复要求，但不能抹去原验收。历史运行无封印时明确标记“历史运行未启用”，不补造已通过的检查记录。

网页显示原目标、封印版本、各节点原验收及阶段检查记录；缺少证据显示待检查，封印失败显示暂停原因与重新制定方案入口。不能把字段完整性检查称为语义正确的证明，不能声称任意长任务绝不偏离。

边界：此轮不做持续任务队列、知识提速、新沙箱或自动经验升级。文件越界和伪造完成复用现有门禁；任意 shell 行为仍依赖沙箱、权限与执行后文件审计。保持旧数据、未知费用、权限和原预算；实测只用员工产物。JJ 本轮累计 $2 授权不变，费用核对后才启动新实测。
