# 沙箱与日志生命周期：第二批

用户已批准第二批：复用 OpenShell、Docker 和文件系统能力，补沙箱磁盘核对、完成后回收、可查询日志归档及故障/持续验证。沿用现有 Windows 工作区与 JJ 部署，凭据、预算及旧数据保留。本批先实现并验证无模型的基础能力。

## 实现选择

- 继续使用固定 OpenShell 0.1.2 CLI、mTLS、1 CPU / 512 MiB、空网络策略和当前执行器；不改 Docker 管理权限，不安装新组件。官方 stop 保留存储，delete 才回收沙箱。删除必须用固定身份、完整交付和明确确认，不能使用 --all。
- 在既有受控远端 Node 脚本中统计 /sandbox 与 /tmp 普通文件逻辑字节、条目及文件系统剩余空间。工作区沿用 20 MiB、128 文件、512 条目；临时目录门禁选 64 MiB / 4096 条目，磁盘剩余门禁 256 MiB。命令运行中周期检查，超限终止命令并保留未知现场。这是应用层监管，不宣称硬磁盘配额。
- 固定 CLI 创建帮助没有通用磁盘配额选项；硬配额需要管理员验证存储驱动支持。本批不扩大 driver_config 权限，也不改系统挂载。
- 网页设置可列出本机已登记沙箱及上次磁盘核对，并显式核对当前容量、预览完成沙箱回收。已停止沙箱的核对会显式启动原 /bin/sleep 工作负载，然后只读检查；不调用模型。完成交付与沙箱版本一致、无活动/未知操作时才可确认官方 delete。
- 后端维护复用同进程 OpenShell 执行器的队列；原员工 RPC、目录授权、设备权限不扩展。持久记录删除意图，再单次调用官方 delete；中断后只查询原 ID，不重发删除，不把 deletion accepted 当成完成。
- 归档仅处理完整且已完成、无未知操作的日志，压缩为 gzip，原文本 SHA-256、大小及快照固定。先写入并校验归档，明确确认后再回收原热日志；readRun/listRuns/备份继续读取相同事件。归档日志不允许追加，损坏不能回退为成功。失败/可恢复现场不归档。
- 本批无默认自动删除，旧发布及缓存仍只读。所有维护入口不接受任意路径或 shell 命令。真实模型长期任务需另行核对原额度；不擅自提高预算。

## 验收边界

本地真实文件测试空间/条目超限、压缩完整性、版本变化、链接、重复确认与中断；既有 OpenShell 协议夹具验证单次删除和身份保护。JJ 实际验证固定沙箱的磁盘、网页、重启与可复测交付；不覆盖当前环境做备份恢复，不删除生产原始资料做实验。短时资源持续实验与多小时员工自主执行分别报告。
