# Weave P0 并行开发协调计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Each worker follows its own researched implementation brief; shared integration is sequential.

**Goal:** 在另一位 Agent 继续 Checkpoint 一致性工作的同时，并行交付成员只读工作台、可选观测摘要导出、七维核心评测三个独立切片。

**Architecture:** 复用现有身份/资源授权、React、观测摘要与 OpenTelemetry、Promptfoo。保留当前执行和恢复门禁；不新增身份、遥测或评测引擎。

**Tech Stack:** 当前固定 Node/TypeScript/React、openid-client、DSH、OpenTelemetry、Promptfoo。

**Spec:** `docs/superpowers/specs/2026-10-20-enterprise-foundations.md`；身份、观测、评测沿用各自 2026-10-20 实施计划；调研基线 `docs/research/reuse-and-ai-delivery-estimate-2026-10-29.md`。

## Global Constraints

- 用户明确要求多 Agent 并行。当前 linked worktree 的 `main` 继续保留，不新建分支、不暂存/提交/推送、不部署。并行编辑通过文件归属隔离，保留其他 Agent 的未提交修改。
- Checkpoint 外部 Agent 独占：`app.ts`、`db.ts`、`local-execution.ts`、coordinator、task/checkpoint/recovery、trace/archive/storage 及其公共测试。当前团队只读这些文件。
- 每条线先核对已实现能力和固定依赖、查官方来源，保存调研和详细计划，经主协调者核对与向用户说明后实施。不重新询问用户已授权的常规实现选择。
- 只做本地可逆开发；不读取真实凭据/生产数据库，不调用付费模型，不扩大预算、权限或未知费用处理规则。
- 未验证的企业执行/恢复保持关闭；前端可见不构成后台授权，观测数据不构成业务成功，合成数据不构成真实模型验收。
- 各自使用独立 `.private/p0-*-20261029` 目录。优先纯函数、HTTP、组件及隔离数据库；全量类型检查/构建由 root 集中执行。
- 依赖与锁文件仅主协调者按已核对的固定版本串行修改；需要跨边界文件先上报，不相互覆盖。

## 共享接口预检

| 配对 | 共享点 | 处理 |
| --- | --- | --- |
| 成员 / 观测 | 身份会话、诊断权限 | 两线均消费已有服务端权限。观测管理接口仍限定既有角色；不借成员入口扩大诊断权限。 |
| 成员 / 评测 | 权限与交付证据 | 评测只读产品合同，不改成员组件；实际权限断言优先已有资源测试。 |
| 观测 / 评测 | 事件摘要、失败语义 | 固定现有摘要合同，评测不把投递成功解释为业务成功。 |
| 三线 / Checkpoint | app 生命周期、trace、归档 | 不编辑这些文件；观测使用已有观察接口，成员使用现有 HTTP，评测消费已有合同。 |
| 任务1 自洽 | 成员入口与管理入口 | 不将 identityAuthorized 全局放宽为所有已登录用户；采用独立范围入口。 |
| 任务2 自洽 | 导出成功与未知应答 | 统计仅依据实际 exporter 应答；默认关闭不外发，测试使用自有本机 collector。 |
| 任务3 自洽 | 32个案例与真实验收 | 案例数量不是通过数量；分开 fixture、产品功能、历史证据与 fresh 模型，不填充虚假通过。 |
