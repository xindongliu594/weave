## 实施顺序与所有权

1. **恢复隔离（主线）**：先收口已有 Task 2c.3 未提交实现；类型/相关回归/构建/独立审查。随后按 archive-writer-fence 既有 Task 2c.4 完成 approve/retry 的目标 writer；再覆盖其余写者与 source capture。企业 task profile 在恢复门禁未验收前保持关闭。
2. **人员管理（独立并行）**：A2 Task 1，复用现有身份 schema、会话与 audit v2。实现人员/成员管理 API、version CAS、epoch 撤会话和最后管理员保护；父任务统一接 app/catalog，避免与恢复主线冲突。后续按 A2 Tasks 2–9 实现资源范围、来源限制、效果前撤权和人员网页。
3. **周期维护（独立并行）**：复用现有 storage inventory/retention 与备份 manifest，先完成只读报告生成及受限 CLI，保留 unknown/failed 状态。提供 systemd service/timer；无机器身份不得模拟管理员 cookie 调生产 API。不得删除文件或新建模型请求。
4. **外部工具效果**：按 C1 既有合同接工具目录、审批与执行 wrapper；核对 intent/receipt/outcome query，未知操作不能重放；compensation 独立批准。
5. **长期部门任务**：在上述授权/恢复基础上接现有 coordinator 持久队列、唤醒和退避，复用系统调度，不装进程内 Jobs 作为持久引擎。
6. **经验发布与插件**：继续现有 SkillX/知识版本/DSH registry 链；补提炼与评测门禁、私有发布/回退、复用统计；工具/服务/网页三种插件分别验兼容性，成熟插件优先。
7. **评测与审计**：复用 Promptfoo 离线桥与现有 audit outbox，将业务事件、查询与周期健康接到用户页面；保持脱敏与有界保留。
8. **集成与交付**：每片保存结果与限制，最后在 JJ 验证实际服务/网页、恢复和备份链。生产变更遵循原部署边界，付费调用另按已有授权核算。
