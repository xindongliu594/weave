# 经验发布与再次选用 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to execute this plan inline. Preserve earlier work and update the checkboxes with actual evidence.

**Goal:** 验证不同真实工作形成经验候选、审核发布，以及后续员工自主检索选用的闭环。

**Architecture:** 复用既有成功工作投影、候选审核发布、知识版本与 DSH Skill Provider。先补隔离串联回归；只在发现阻断时修复共享实现，不新增记忆库或安装第二套执行系统。

**Tech Stack:** 当前 Node / TypeScript / React / PGlite / DSH，无新增依赖。

**Spec:** docs/knowledge-learning-loop.md；选型见 docs/research/reuse-publication-loop-2026-10-11.md。

## Global Constraints

- 默认门槛保持 3；沿用原 1 个真实成功工作，失败、读取及重复恢复不得增加次数。
- 当前JJ累计授权$2.60、阶段$0.52；2026-10-12最后批准库存$0.30、后续$0.09，总64/单节点最多40。AI实际给QA38次、经理32次。旧费用和未知预留保留，每日$20及原门禁不变。批准的唯一修复后续验已停止，不能自动追加。此前额度及48/32记录作为历史保留。
- QA/经理原授权只含两份验收方法。新的已发布方法需在本轮验收范围内明确授权，旧运行快照不修改。
- 员工产生交付、QA 核对、经理验收；Codex 不补写交付冒充成功。
- 候选发布为普通经验；成为 Skill 仍需明确方法标记。后台不自动生成工具或增加权限。
- 如员工未采用方法或验收失败，记录实际结果，不能为达到次数改事件、数据库或门槛。
- 时间、Token 和配置费率登记费用分别保存；没有可比首次工作时收益仍为未验证。

## Review Focus

1. 发布重试只产生一个文档，既有人工正文不被补检覆盖。
2. 普通经验不自动成为指令，未授权员工不能发现或读取新方法。
3. 新方法编辑不替换旧批准快照，哈希损坏或来源变化阻止不可信发布。
4. 三份不同工作的真实采用与封存可核对，不用复制任务凑次数。
5. 新规划及恢复预留进入共同上限；未知费用不清零。
