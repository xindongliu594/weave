# 企业可观测性与归责审计 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 使管理员能够从一次人类批准查到员工、工具版本、实际效果与费用证据，及时发现卡住、容量不足和观测降级，并在明确启用时仅通过 OTLP 导出受限摘要。

**Architecture:** PostgreSQL 中的业务事务、`human_audit_events` 与原运行 JSONL 分别保持自己的事实源；一个共享的摘要合同连接审计投影、已有 trace、诊断和可选 OTel Logs exporter。复用 DSH 已有执行事件、员工工具 guard、为伍 coordinator/supervisor、automation 通知和存储治理；不增加 Agent、执行器、调度引擎或收费账本。

**Tech Stack:** TypeScript/Express/React/PostgreSQL；DSH `0.1.5-rc.1`、AgentTeams `0.1.20`、OpenShell `0.1.2`；已安装的 OpenTelemetry JS Logs SDK `0.220.0` / API `1.9.1` / resources `2.9.0`，以 runtime 显式固定依赖集成。

**Spec:** `docs/superpowers/specs/2026-10-20-enterprise-foundations.md`；总计划 `docs/superpowers/plans/2026-10-20-enterprise-foundations.md` 的 D2。

状态：详细计划，未实现、未验收。2026-10-20 核对 HEAD `e2cbf2a6adbb4d37426567679dca7f5cc2d3bb6a` 及当前共享工作树；工作树中的 A1 接线、B1 canonical 提交等未提交代码仅为调查对象，不代表其独立审查、部署或验收完成。本文件没有授权新模型费用、生产变更或 JJ 发布。

## Global Constraints

- 服务部署仍在 JJ；不在 JJ 加载大型语言模型。
- 保留既有数据、未提交成果、凭据、旧权限、历史费用与未知预留；不自动提高 API 金额或次数。
- 新功能先核对固定版本和成熟复用方案，再完成详细计划，之后实现。
- 身份鉴权和资源授权发生在幂等响应缓存之前；幂等键按主体隔离。
- 权限收回即时影响新的读取、工具调用和恢复；历史授权快照仅用于审计，不能恢复已吊销权限。
- Checkpoint 不回滚已发生的外部效果、账本、审批或审计。结果未知的有副作用操作必须核对，不能自动重放。
- 归档清理只操作本应用可证明拥有的目录；活动运行、未决操作、保留要求及恢复所需版本不可删除。
- 每项进度分别标注：未开始、实现中、本地已验证、JJ 已验证、真实业务已验证、受阻；只有所需证据齐全才能完成。
- 日志、指标和外发副本不能成为权限、效果成功、账本结算或发布通过的事实源；OTLP 故障不能阻塞原执行，必需审计持久化故障则拒绝新的受审计变更。
- DSH 的反馈授权 OTel 后端保持原语义；不伪造反馈、不把 `FEEDBACK_ONLY` 改成未支持的 live 模式、不自动上传历史会话。

## Review Focus

- 撤权、会话失效、伪造 actor/关联 ID 或幂等命中：以当前服务端授权决定访问；审计保留原批准人和实际执行者，不能从 body 获得身份。（Tasks 1、3、7）
- 业务提交成功而 JSONL/响应/投影失败，以及两个投影 worker 竞争：成功审计同事务，投影按源事件 ID 幂等；不能重做业务或并发写坏活动运行日志。（Tasks 2、3）
- 恶意插件结果、自由文本秘密、超长字符串、循环对象和未知事件：外发只接受严格构造的固定字段摘要，拒绝未知值且队列有界。（Tasks 4、5）
- exporter 永不回调、持续 429/503、关闭时挂住、积压溢出：运行继续，内存/等待有上限，丢弃和未确认投递可见。（Task 5）
- 人工审批/模型等待被误报停滞、旧 lease 看似健康、磁盘探测失败或任务沙箱持续占用：分别展示状态和采样时间，不自动重启、释放容量或删除现场。（Task 6）

## 共用类型与数值（均为本计划新增合同）

```ts
type Correlation = { requestId?: string; modelRequestId?: string; correlationId: string; projectId?: string; runId?: string;
  taskId?: string; attemptId?: string; operationId?: string; parentOperationId?: string;
  approvalId?: string; mergeId?: string };
type AuthorityEvidence = { decisionId: string; checkedAt: string; policyVersion: string;
  principalKey: string; departmentIds: string[]; membershipVersions: {departmentId: string; version: number}[];
  grantVersions: {kind: 'employee'|'capability'|'device'; id: string; version: string}[];
  permissionSha256: string; approvalId?: string; budgetApprovalId?: string };
type AuditActor = { kind: 'human'; userId: string; orgRole: 'member'|'admin'|'auditor' }
  | {kind: 'local-owner'} | {kind: 'device'; deviceId: string}
  | {kind: 'system'; service: string} | {kind: 'unidentified'};
type AuditInput = { eventId: string; action: AuditAction; actor: AuditActor;
  requestedByAuditId?: string; executedEmployee?: {employeeId: string; agentId: string; sessionId: string};
  authority?: AuthorityEvidence; correlation: Correlation;
  resource: {type: AuditResource; id: string; departmentIds: string[]; version?: string};
  outcome: 'success'|'denied'|'failure'|'unknown'; reasonCode?: AuditReason;
  changes: AuditChanges };
```

`AuditAction/AuditResource/AuditReason/AuditChanges` 在 Task 1 定义严格 discriminated union，不接收 `Record<string,unknown>` 的任意字段。action 至少覆盖 identity、membership、project plan/approve、run cancel/recover、tool approval/dispatch/result/reconcile、task merge、budget policy、knowledge publish/withdraw、capability/device/model configuration、backup/restore/cleanup、audit read/export。changes 每个 action 只允许 ID、版本、SHA、枚举和有限数字；禁止原参数/正文/错误消息。

上面的 `authority?` 只为未认证拒绝、历史兼容及已发生效果的证据接收保留；Task 1 的 action union 必须对新批准、授权变更、新 dispatch/merge 等成功效果强制要求当前 `AuthorityEvidence`。不能让调用者以省略字段绕过当前权。A2 原授权人及 `authorized_epoch` 与当前 epoch 比较；自然浏览器 session TTL 到期不等于后台原授权撤销。

- actor 是实际发起此边界的认证主体。系统执行为 `system`，员工信息置 `executedEmployee`，原真人批准用 `requestedByAuditId` 连接；员工 ID 不是可登录 `Principal`。device 结果回执记录 device actor，不伪装批准人。未认证攻击使用 `unidentified`；不把未验证 token/subject 或猜到的用户 ID归为真人。既有历史 actor 不回填。
- `AuthorityEvidence` 是当次准入结论的审计副本，只能由 A2/C1 可信代码构造。批准快照、当前权限、scope/capability hash 分别保留；快照不授当前权。接收原已发生效果的迟到证据可以记录 `authority-revoked`，不得由此触发新的 dispatch/merge。
- 请求进入后端生成 UUID `requestId`，以新 UUID `correlationId` 为默认。header/body 中的 request/correlation/actor 不覆盖它；服务内可信调用显式传递。run 批准时固定 `snapshot.auditContext={correlationId,requestedByAuditId,requestId}`；后台 callback 沿 run 的该可信来源关联，并另留实际当前请求 ID。现有 runtime `TraceEvent.requestId` 是模型请求 ID，映射为 summary 的 `modelRequestId`，绝不覆盖 HTTP request ID。run、operation 的 correlation 通过 DB 外键/固定 scope 得出，不能由客户端 query 将两个无权对象关联。响应只返回 `X-Request-Id`；机器 credential、CSRF、Cookie、OIDC subject/sessionId 不进入通用审计/外发。
- 字段限制：ID 128 字符、固定 hash 64 hex、版本 128、departmentIds 最多 100 且排序去重、changes 编码最大 8 KiB、单审计输入最大 16 KiB。数值必须有限且满足对应 schema。未知键、原型、自定义 getter/循环对象、无效时间拒绝；入库使用可信新对象。
- `human_audit_events` 保留原列；新增 `schema_version=2`、`source_event_id UNIQUE`、`correlation_id`、run/task/attempt/operation/approval/merge 引用、`requested_by_audit_id`、`executed_employee`、`authority_evidence`、`resource_versions`。检查约束增补 `unidentified` actor 和 `unknown` outcome；不改变人类外键条件。旧事件保留 null 新列与 schema 1。
- `audit_outbox` 保留 `published_at`，其唯一含义为**本地 DB 投影已提交**，绝不表示 OTLP 收到。增补 `attempts`、`next_attempt_at`、`last_error_code`；仅固定错误码。新增 `audit_run_projection(audit_event_id PRIMARY KEY, run_id, correlation_id, occurred_at, summary)`，只存受限摘要，可从 canonical audit 重建。索引 `(run_id,occurred_at,audit_event_id)`，不加另一份长文本档案。
