# 编排模板、任务匹配与组织复用：调研和设计建议

日期：2026-10-18。状态：需求记录与设计建议；尚未实现模板库、自动路由或临时团队新功能。本轮只读检查代码及官方/维护者资料，没有安装依赖、修改 JJ、创建员工或调用付费模型。

后续源码调研见[开源实现比较与接入建议](orchestration-reuse-source-audit-2026-10-18.md)：补充 Cortex 的策略匹配、team-gui 的真实公共接口边界和 dsh-workflow 仓库不可用情况。

> 同日进一步核对修正：下文早期“尚未支持跨部门”的判断不准确。`collaboration.ts` 和 `POST /projects` 已支持显式挑选外部门员工、来源校验与版本快照；未实现的是自动组织推荐与独立临时团队。Cortex 的隔离真实规划也已完成，见[试验报告](../validation/cortex-planning-pilot-2026-10-18.md)。当前执行建议以[任务驱动组织设计](../superpowers/specs/2026-10-18-task-driven-organization.md)和[第一段实施计划](../superpowers/plans/2026-10-18-task-driven-organization.md)为准：先补自动推荐与交付标准，沿用现有合同桥接，再做模板发布检索。下文保留早期调研过程，不作为最新能力状态。

## 用户目标

将可复用的多 Agent 协作方式保存下来。新任务进入后，快速识别适合的编排方式，选用已有部门或其他组织形式组织员工工作。已验证的工作继续沉淀，记录复用前后的耗时、Token、费用和质量。延续先调研、再计划、后开发，优先复用 DSH 插件与现有知识能力。

默认建议：优先匹配已有部门及获授权员工；不足时生成待确认的组队建议。模板命中不直接创建部门、扩大权限或开始付费执行。临时项目团队与跨部门协作分阶段接入，不能将现有单部门执行器宣称为已支持跨部门。

## 当前代码和固定依赖

- `packages/contracts/templates.ts`：岗位、软件研发部和资料研究部的静态模板。
- `packages/contracts/organization.ts`：按成员顺序交接的模板草案；不具备模板索引、推荐或可复用编排目录。
- `apps/api/src/project-planning.ts`、`organization-task-planning.ts`：按新目标生成方案、合同与依赖，确认后封存。现有示例不是所有业务的固定执行流程。
- `services/agent-runtime/host.mjs`、`handoff.mjs`：通过原生团队工具组织工作，运行中锁定已批准范围，子团队深度为 0。
- `apps/api/src/knowledge-reuse.ts`：按不同成功工作统计知识采用，保留来源证据并生成待审候选。可复用生命周期思路，但当前对象不是编排模板。
- 已安装 `@nanmicoder/dsh-agent-teams@0.1.20`，DSH 为 `0.1.5-rc.1`。本轮检查安装包 README、`lib/profiles.js`、`lib/types/profiles.d.ts`，不以最新上游替代当前事实。

## 现成实现的选择

| 实现 | 核对结果 | 决策 |
| --- | --- | --- |
| [dsh-agent-teams](https://github.com/NanmiCoder/dsh-agent-teams) | 当前安装包已有命名 `profiles`；`taskPlanning: seed` 固定种子流程，`captain` 按目标规划。Profile 支持成员、依赖和审查策略 | 直接复用既有团队执行和 Profile 能力；先做隔离兼容验证，不重写调度器 |
| [dsh-agent-team-gui](https://github.com/toolclub/dsh-agent-team-gui) | 维护者提供团队定义、不可变版本、无凭据 recipe、成员选择和动态 DAG。声明 1.3.0 兼容当前 DSH 范围，依赖原生 Web 服务 | 作为定义/recipe 适配候选。未安装、未通过为伍验证；不能把其运行记录直接替代现有预算和交付封存 |
| [LangChain Router](https://docs.langchain.com/oss/python/langchain/multi-agent/router) | 可用规则或一次模型分类选择专家，与持续协调的主管分工不同 | 参考候选选择职责；本轮不为路由安装第二套 Agent 框架 |
| [DSH 社区目录](https://github.com/dshplugin-app/deepseek-harness-plugins) | 插件发现入口，能力和版本仍须查看维护者实现 | 继续用来发现插件，目录收录不当作兼容性验收 |

固定安装包的重要边界：Profile 最多 16 项、每项最多 32 个种子任务；种子任务只有 id、subject、description、assignee、dependencies，不能保存为伍完整的文件交接、预算和验收合同。不能把扩展字段塞入 Profile 后假设它会执行或校验。公共包导出也不包含 `profiles` 子路径，避免依赖内部深路径导入。

为伍应保存匹配元数据与完整产品约束，向原生插件传入兼容的 Profile/已批准计划。公司模板可以很多，但每次只提供相关候选或选中模板；具体桥接方式在隔离探针验证后确定。

## 三个独立对象

| 对象 | 保存什么 | 不继承什么 |
| --- | --- | --- |
| 编排模板及版本 | 适用/排除场景、角色槽位、步骤依赖、可调整范围、交接/验收要求、所需能力、来源、证据、生命周期 | 旧项目凭据、实际花费、完成状态、旧员工权限和具体文件内容 |
| 部门或项目团队 | 员工归属、职责、可用能力、知识授权，以及角色到具体员工的绑定 | 不因模板需要某工具就自动授予该权限 |
| 单次运行快照 | 新目标、选中模板版本和哈希、实际员工、具体任务图、文件版本、批准权限及预算、运行记录 | 不把旧成功节点当作本次完成，也不重放旧外部操作 |

同一部门可使用多个模板，同一模板可被不同获授权部门采用。模板角色使用能力要求而不是写死员工 ID。部门删除或归档后，其新任务绑定失效；历史运行和有权保留的模板来源证据继续按既有归档规则保存，不把旧关系自动改接到其他部门。

模板属于工作方法的一种结构化定义，可在公司统一能力目录中被发现；执行时仍使用对应 DSH 格式。编排模板、Skill、MCP 与插件具有各自格式，统一检索不代表把模板假装成可直接调用的工具。

## 推荐的新任务流程

1. 从持续需求对话取得当前目标、交付类型、约束及任务版本。
2. 先按发布状态、可见范围、运行器能力和授权筛选模板；再按任务/交付特征检索少量候选。明确指定模板时也经过同样校验。
3. 简单且明确的匹配可走规则；存在歧义时，将候选摘要交给已有规划模型选择并说明依据。优先合并到原方案规划调用，避免固定增加一轮路由调用。所有真实调用沿用费用收据和授权。
4. 选定模板后才读取完整定义，绑定获授权员工，生成符合新目标的具体任务图。多人是否有必要也纳入选择，简单工作保留单执行员工的路径。
5. 网页展示选择原因、采用版本、团队、流程、权限缺口、预算和与模板的差异；按既有规则确认后执行。匹配服务没有创建团队或执行副作用。
6. 匹配不到、权限不足或判断不确定时，明确返回未命中/待补充状态，转入现有新方案规划，不强套模板或偷偷放宽权限。
7. 执行结果关联模板版本。失败原因和人工纠正也进入评估；达到证据条件后形成模板修订候选，不自动覆盖已发布版本。

缓存只保存有界候选/选择引用；键包含任务版本、目录版本、授权和能力状态。读取缓存后仍重新检查权限与可用性，变化即失效。不能按一段相似需求缓存整份授权或旧运行。

## 三种接入方案比较

- **推荐：现有 AgentTeams + 薄模板/匹配层。** 保留恢复、预算和产物合同；复用 Profile 与任务工具，只补现有产品没有的目录、路由和绑定。需要验证 Profile 不绕开产品门禁。
- **整套接入 team-gui。** 可复用更多模板和导入界面，但新增另一套团队/运行状态以及原生 Web 依赖，接入现有账本的成本更高。先调查公共定义 API 可否独立复用，再决定引入范围。
- **迁移 LangGraph 等编排框架。** 可获得更多通用路由能力，但需迁移已验证执行与恢复链。当前需求不足以支持这一迁移成本。

## 建议分期和实际验收

以下是分期建议，尚非已批准的详细实施计划。

1. **模板保存及人工选用。** 先隔离验证原生 Profile 的固定/动态两种模式与现有批准合同组合；从已验收研发和办公案例提取候选定义，验证版本固定、角色绑定、权限拒绝、导入不携带凭据。后台和网页沿用当前流程。
2. **自动匹配并生成方案。** 用已标注的小任务集检查适配/不适配/歧义/缺权限/不支持拓扑，输出候选命中率、误选率、回退率、P50/P95 延迟及路由 Token。真实业务验收须使用员工实际产物，协议夹具不代替模型验收。
3. **运行反馈与复用效果。** 记录规划和执行分别消耗的 Token、费用、墙钟时间、成功率及返工次数。按可比任务、模型、权限和缓存条件比较首次与复用；样本不足或更慢照实展示，不承诺提速比例。
4. **临时团队及跨部门。** 在模板复用通过后，独立扩展组织绑定及身份/授权。现有执行器只支持单经理团队，其他拓扑先标记不支持，不能悄悄降级为已支持的流程。

必要回归还包括：新版本模板不影响运行中的旧快照；重启后恢复原模板版本、人员、DAG 和预算；完成节点不重复；未知外部操作不重放；撤销权限后的目录/缓存不可继续使用；同一角色不能同时充当要求独立的作者与验收者。
