# 文件与数据容量

打开网页“系统设置”，找到“文件与数据容量”。JJ 入口默认是 `http://127.0.0.1:4312/#settings`；Windows 本机默认是 `http://127.0.0.1:4310/#settings`。升级后刷新网页即可。

1. 查看运行档案、数据库、知识原文、操作收据和本机工作区的占用。部署目录统计可能包含上表数据，不能直接相加。链接不跟随，扫描未完成时只显示已经核对的字节下限。
2. 点“生成清理预览”，查看具体运行、文件、可回收字节和保留原因。当前仅支持已完成的 native 本机工作区中、与正式交付完全一致的普通副本。
3. 核对清单后点“确认清理上述副本”。预览 30 分钟有效，执行前再次检查整批状态、文件身份和哈希。活动任务或未知本机操作会阻止清理。文件变化时重新预览。
4. 从“清理记录”看结果。服务中断后点“核对中断结果”，只读取当前文件和正式交付，不会续删。重复确认已经结束的清理只读取结果。

清理保留运行快照、原始日志、会话、检查点、正式交付、费用、知识和凭证，不删除目录。失败、停止、未知或未登记的现场也保留。恢复已完成副本仍使用原来的正式交付版本。

容量门禁沿用单运行档案 64 MiB、全部运行档案 1 GiB；新增文件系统可用空间低于 256 MiB 时阻止新运行、模型请求和受控命令。需求对话仍不占执行预算，但需要可写磁盘。空间门禁会停止新增工作，不会自动删除旧证据，也不构成容器硬磁盘配额。

预览最多核对前 1000 个工作区条目、每个工作区最多 512 条目、清单最多 4096 个文件。重复有效清单复用记录；清理元数据达到 1000 条或 16 MiB（含结果预留）时停止新增，保留旧记录。整理历史清理记录的网页入口尚未提供。

清理记录纳入现有加密备份；旧备份缺少新表时恢复为空表。跨目录或设备恢复的旧预览不能直接授权删除，必须在当前环境重新预览。恢复实验应使用隔离目录。[JJ 数据与维护](deployment-jj-quickstart-2026-10-09.md#数据与维护)

OpenShell 的配置及操作映射、旧发布、依赖缓存和备份目前只读盘点。容器内部磁盘尚未统计，自动保留周期、旧发布回收和多小时耐久测试仍待完成。[本批验收与截图](validation/storage-governance-2026-10-11.md)
