# 文件与数据容量

打开网页“系统设置”，找到“文件与数据容量”。JJ 入口默认是 `http://127.0.0.1:4312/#settings`；Windows 本机默认是 `http://127.0.0.1:4310/#settings`。升级后刷新网页即可。

1. 查看运行档案、数据库、知识原文、操作收据和本机工作区的占用。部署目录统计可能包含上表数据，不能直接相加。链接不跟随，扫描未完成时只显示已经核对的字节下限。
2. 点“生成清理预览”，查看具体运行、文件、可回收字节和保留原因。当前仅支持已完成的 native 本机工作区中、与正式交付完全一致的普通副本。
3. 核对清单后点“确认清理上述副本”。预览 30 分钟有效，执行前再次检查整批状态、文件身份和哈希。活动任务或未知本机操作会阻止清理。文件变化时重新预览。
4. 从“清理记录”看结果。服务中断后点“核对中断结果”，只读取当前文件和正式交付，不会续删。重复确认已经结束的清理只读取结果。

清理保留运行快照、原始日志、会话、检查点、正式交付、费用、知识和凭证，不删除目录。失败、停止、未知或未登记的现场也保留。恢复已完成副本仍使用原来的正式交付版本。

容量门禁沿用单运行档案 64 MiB、全部运行档案 1 GiB；新增文件系统可用空间低于 256 MiB 时阻止新运行、模型请求和受控命令。需求对话仍不占执行预算，但需要可写磁盘。空间门禁会停止新增工作，不会自动删除旧证据，也不构成容器硬磁盘配额。

预览最多核对前 1000 个工作区条目、每个工作区最多 512 条目、清单最多 4096 个文件。重复有效清单复用记录；清理元数据达到 1000 条或 16 MiB（含结果预留）时停止新增，保留旧记录。整理历史清理记录的网页入口尚未提供。

清理记录纳入现有加密备份；旧备份缺少新表时恢复为空表。跨目录或设备恢复的旧预览不能直接授权删除，必须在当前环境重新预览。恢复实验应使用隔离目录。[JJ 数据与维护](deployment-jj-quickstart-2026-10-09.md#数据与维护)

OpenShell 的配置及操作映射、旧发布、依赖缓存和备份继续保护。第一批结果见 [原验收](validation/storage-governance-2026-10-11.md)；第二批增加以下维护入口，见 [沙箱与日志验收](validation/sandbox-lifecycle-2026-10-11.md)。

## 沙箱与完成日志

1. 展开“OpenShell 沙箱可写目录”，点对应运行的“核对容量与文件版本”。停止的沙箱会启动原工作负载，检查原 ID、授权与文件版本，不调用模型。列表显示 /sandbox、/tmp 的普通文件逻辑字节及核对时间。
2. 已完成、费用和外部操作均已核对、与正式交付版本一致的沙箱可“预览回收”。确认清单后点“确认回收沙箱”，调用固定 OpenShell 官方删除接口。失败、停止中的未完成运行、未知结果或版本不一致均保留。删除受审批、空闲和设备绑定限制，正式交付不删除。
3. 展开“最近 50 次运行档案与恢复入口”，完成运行可“预览日志归档”。确认后 gzip 与 manifest 校验完成才删除原热日志；事件、列表和备份仍可读，封存日志不再追加。净节省计入 manifest，过小日志没有净收益时保留。
4. 操作中断后从“清理记录”点“核对中断结果”。只查询原沙箱 ID 或原日志；沙箱仍在、归档未核对时可再次查询，不重发删除。不要把“删除请求已接受”当作沙箱已回收。

执行器每 250 ms 检查受控命令容量：/sandbox 20 MiB、128 文件、512 条目；/tmp 64 MiB、4096 条目；文件系统可用至少 256 MiB。临时条目删除/重命名最多重扫三次，超限或持续无法核对会终止命令并保留未知现场。这是应用监管，短时采样可能遗漏突发写入；不是 OS 硬磁盘配额。

镜像层、Docker 日志和实际分配块数不在沙箱目录统计内。没有默认自动删除；旧发布/缓存回收、清理历史整理及多小时耐久运行仍未验收。当前 API 仅维护本机同进程登记的 OpenShell 设备，不能让任意远程客户端执行维护。大档案备份继续使用既有目录备份流程，恢复实验放在隔离目录。

## 保留与维护建议

展开同页“保留与维护建议”。这是一组只读建议，按运行的**完成时间**计算，最多查看最近 50 次运行；每次刷新不新增清理记录、不启动沙箱、不调用模型。默认建议：

| 资料 | 建议保留 | 维护方法 |
|---|---|---|
| 已完成热日志 | 至少 24 小时 | 预览日志归档，确认后校验压缩 |
| 已完成工作区副本、沙箱 | 至少 7 天 | 预览并确认回收；交付原件保留 |
| 软件发布 | 当前版本、最新 3 个版本、所有共享依赖来源 | 人工核对后备份归档，无自动删除入口 |
| 备份 | 最近 30 天，以及最新 3 份 | 先完成隔离恢复验证再人工归档 |
| 依赖缓存、Docker 镜像与日志 | 无自动到期 | 独立盘点；本页不授予系统删除权限 |

建议不是可删除证明。费用待核对、未完成、失败、未知操作及不合法完成时间不会出现在建议中；点击后仍沿用原有的授权、版本、档案完整性和空闲检查。工作区按钮会预览**全部**符合既有规则的本机副本，不只是所在行；以具体预览清单为准。保留时间仅约束建议入口，原有手动维护入口仍可由用户提前预览。

不要直接删除旧发布目录：多个版本可能通过链接引用旧版本的 `node_modules`。先查明真实依赖来源，保存可恢复备份，再做人工维护。没有把“超过建议天数”视为自动删除授权。
