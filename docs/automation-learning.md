# 自动化、长期监督与经验整理（最小版）

工作台的“自动化与经验”提供五个功能页签。本模块不调用付费模型、不向外部发送消息，也不绕过项目的批准、工具审批和预算机制。

## 定时计划

选择现有项目、首次触发时间（浏览器本机时区）、单次或固定间隔。保存时冻结项目当前完整方案与策略，包括员工、工具范围、资料选择及文件选择；后续修改源项目不会静默扩大既有计划的权限。

到期后事务性地创建一个 `DRAFT` 项目、方案版本、派发记录和通知。必须在项目页重新检查并批准，才会进入运行队列。创建草案不会消耗模型额度。取消计划仅停止后续触发，不会取消已经派发的项目。

应用后台运行时约每 10 秒检查；关闭应用期间不会执行。重启后，间隔计划错过多次触发只补一份草案，下一次时间跳到未来，避免恢复后批量积压。单次计划补发后结束。暂停、恢复和取消均带版本检查；同一计划和时间组合有数据库唯一约束，派发与游标推进在同一事务中完成。

计划时间保存为 UTC 时间点，界面以本机时区显示。固定间隔不是日历时区 Cron；夏令时下仍按固定秒数间隔。

加密备份包含计划、派发记录、通知、监督记录、知识候选和改进评测。恢复备份后，原先生效中的计划会暂停，待回复的经理消息会取消；请核对当前配置后手动恢复计划或重新发消息，避免恢复旧备份直接触发后续动作。已结束消息与人工评审历史保留。

## 应用内通知与跨重启监督

已批准运行进入完成、失败、中断或取消终态时，后台补检并持久保存一条通知。重复检查、重启均不会重复通知；已读状态也持久保存。通知中保留运行和项目标识。当前没有邮件、聊天软件或操作系统推送。

运行中每小时记录状态、经过时间、调用次数、已确认费用、租约是否过期；终态额外记录一次。监督器不改变运行状态、不延长截止时间，也不会自行恢复执行。原运行协调器继续负责租约、心跳、预算和中断核对，用户通过原恢复流程决定续跑。

“长期”在本版指记录可跨日及跨重启保留，并不表示单个运行能无限执行。原批准策略中的截止时间、调用次数和预算依旧有效。没有宣称完成真实多日耐久验证。

## 知识整理

从已批准运行的知识清单选择资料，读取批准时固定的版本与 SHA256，再次检查知识空间授权及有效性。仅取原文前 12,000 字符生成待审查摘录，超长内容明确标记截断；这是确定性摘录，不是模型总结，也不是自动事实判断。

候选按来源文档和内容哈希去重。人工可修改标题和内容，然后勾选审查确认并发布。目标固定为来源的原知识空间，不能改到更广范围；已归档来源或失效授权会拒绝发布。发布复用知识文档的保存、版本与 Obsidian 索引流程，并以稳定文档 ID 处理丢失响应后的重试。中断的发布租约两分钟后可重试。候选保留原始运行、文档版本、哈希及发布文档标识。

本版仅整理已授权知识文档，尚未自动分析任意代码交付物、抽取语义知识或在后台自动发布。

## 改进评测

记录原方案、改进建议和固定测试案例。每个案例可以约束必含词、禁用词、最大字符数和 JSON 顶层字段（界面支持单案例词语/长度，API 支持最多 20 个案例与 JSON 字段）。案例保存后固定；需要更改案例时创建新候选，防止根据结果调整标准。

手工提供同一案例的改进前后输出后，确定性规则计算逐条通过情况和平均分，保存完整输出、规则、分数和方法版本。不会替用户运行前后模型，规则通过也不证明语义和事实正确。人工评审记录必须说明采用或拒绝理由；采纳需关联本候选评测，且规则分数不能下降。

采纳只是把候选标记为“已采纳，需手动应用”，不会自动更新员工提示、权限或运行快照。回滚撤回采纳记录，同时保留全部评测和评审历史；不会撤销用户随后在其他页面手动做出的员工配置改动。

## 接入与测试

- `migrateAutomationLearning(pool)` 创建 `automation_*` 表；`automationTables` 为备份导出的顺序清单。
- `AutomationLearningService(pool).start()` 启动补检；关闭应用时调用 `close()`。支持注入 `clock`，`tick()` 可用于可重复验证。
- `automationLearningRouter({service,publishKnowledge})` 提供 `/automation/*` API；`publishKnowledge` 复用 `saveKnowledgeDocument(input,id,true)`。
- 主要 API：`/schedules`、`/schedules/:id/state`、`/occurrences`、`/notifications`、`/notifications/:id/read`、`/observations`、`/knowledge-sources`、`/knowledge-candidates`、`/knowledge-candidates/:id/publish`、`/improvements`、`/improvements/:id/evaluate`、`/improvements/:id/review`、`/improvements/:id/history`。

验证命令：`npm run test:integration -- tests/automation-learning.test.ts`。当前 5 项集成测试覆盖冻结授权快照、原子草案派发、九天虚拟停机合并补发、重复检查与服务重建、暂停恢复取消、终态通知去重、已读持久化、跨日监督、知识授权与来源哈希、发布响应丢失重试、固定前后评分、人工采纳与回滚。

`tests/extensions-backup.test.ts` 另有 3 项检查，覆盖扩展表和凭证/文件快照恢复、恢复后计划暂停及消息取消、正在回复时拒绝备份与恢复、旧备份兼容，并实际检查 Windows 嵌套执行档案和 Vault 相对路径的正文保留。

集成运行器为每个测试文件创建独立内存 PGlite，避免单后端的连接启动参数导致跨文件污染。测试使用单数据库连接和虚拟时钟，未验证真正多进程 PostgreSQL 锁竞争或真实多日执行，不产生付费模型请求。
