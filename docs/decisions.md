# 第一版范围与实现决策

本文件保留首切片的历史决策。下文“尚未实现”描述属于当时状态；当前实现及未完成项见 [完成度复核](completion-audit.md)。

## 用户已确认

- 第一版为本地网页版，之后再考虑桌面包装。
- 部门与员工均为可管理实体；长期或一次性取决于用户是否删除，不预设生命周期类型。
- 保留下来的部门后续可以沉淀知识。第一版保存项目/方案历史，为后续知识来源保留关联。
- 统一 API 中转站接入多个模型，每位经理/员工可以独立选择。
- 执行必须可追溯，关联需求、批准方案、员工配置快照、任务尝试、模型/工具调用、消息、用量与交付物。密钥不进入执行日志；历史记录不能因修改或删除员工而改变。
- 员工提示词区分可复用的岗位职能与当前任务指令，当前项目的临时要求不覆盖保留员工的岗位配置。

## 提示词分层接入设计

岗位提示词描述职责、工作方法、输出规范、协作边界，由产品维护的模板约束组织规划模型生成，用户可查看和编辑；模板和生成结果分别记录来源、版本。现有 `agent.instructions` 只有一个自由文本字段，尚无完整模板和版本管理。

任务提示词依据批准的任务目标、输入、依赖结果、交付要求和验收标准，由系统渲染后发给成员。经理负责提出任务及调整建议，系统负责绑定任务与 attempt，变更需留痕；经理的指令不能扩大员工授权或隐式改写岗位配置。

团队协议继续由 AgentTeams 的成员 persona 与 assignment prompt 承担；职能与任务信息通过正式字段注入，不复制 AgentTeams 协议。产品岗位职责已映射到 `memberPersona`，具体任务与验收标准已映射到 `assignmentPrompt`，两者分别进入运行快照和追溯事件。

每次执行保存岗位提示词版本、任务版本、模板版本、实际发出的提示词/消息快照与关联 ID，而不只保存当前可变配置的引用。追溯还要覆盖执行中追加指令和依赖材料版本；可查看记录不代表模型输出可完全复现。

工具权限、文件范围、费用和时限由执行侧强制校验，不能只靠提示词约束。当前正式 Run 已执行费用预留与共享预算、截止时间、取消和模型路由快照；文件与终端权限隔离尚未完成，因此审批接口只允许工具列表为空的纯文本方案。

## 首切片

数据库是真实 PostgreSQL，管理操作不使用浏览器内存或模拟数据作为持久化。历史方案不可覆盖，版本冲突返回 409。删除部门为逻辑删除，历史方案保留配置副本。经理本身可以独立完成小任务，因此允许总人数为 1。

首切片采用 React/Vite + Express，业务逻辑按 contracts、provider、vault、db、adapter 分层。原型与启动包中 Next/Nest 是建议而非执行指令；当前不依赖 SSR 或额外框架装饰器。未来可在不改 API 与共享字段的情况下迁移。

只接入 OpenAI Compatible Chat Completions 的文本、结构化规划和工具调用转换。界面中的文件与终端工具选择目前仍是配置数据；正式审批会拒绝包含这些权限的方案，不宣称已经建立强制隔离。

## 当前已经接通

1. 用户可在本地页面配置中转站，发现模型、测试真实文本调用并用模型生成组织方案。
2. 产品运行时通过 DSH Host 与 AgentTeams 的程序化接口创建 staged team、显式批准并执行，不直接修改 `.agent-teams` 文件。
3. 统一模型目录按运行快照映射到 OpenAI Compatible 中转站；每名员工可使用独立模型路由。
4. 项目版本审批生成不可变 Run 快照，同一项目版本重复审批返回同一个 Run；执行记录保存岗位、任务、模型请求、AgentTeams 操作、用量和结束状态。
5. 正式 Run 已实现预算预留、共享实际用量、截止时间、主动取消和停滞检测；工具权限与不受支持的并发配置在审批时拒绝。

## 下一阶段的明确工作

1. 用用户实际中转站完成多模型、工具调用、用量字段和错误格式的兼容性验收。
2. 建立文件工作区与终端工具的执行侧权限隔离，再开放方案中的对应工具权限。
3. 增加运行租约、outbox 与重启恢复，处理进程中断后遗留的 queued/running Run。
4. 实现 AgentTeams 成员调度的并发限流，不再要求并发上限不少于员工数。
5. 运行 Todo API 真实验收，收集交付物、测试命令和文件差异。

## 暂未满足的契约

管理写接口目前使用版本比较防止覆盖，尚未实现全局 Idempotency-Key。项目审批以项目版本唯一约束去重，但单进程规划锁不能作为多进程运行锁。执行中的 Run 在进程重启后尚不能自动恢复。
