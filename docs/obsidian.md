# Obsidian 知识库

Markdown 文件是资料源。工作台负责授权、版本索引和运行引用，不要求安装社区插件，也不需要模型 API 或 embedding API。

## 当前 Mac

Obsidian 已安装到 `~/Applications/Obsidian.app`。默认 Vault 为：

```
/Users/macmini1/Library/Application Support/AgentDepartment/.data/obsidian-vault
```

在 Obsidian 选择“打开本地仓库 / Open folder as vault”，打开该目录。工作台“知识库”页也会显示实际目录。自定义目录使用 `OBSIDIAN_VAULT` 环境变量；安装后台服务时可同时传入该变量。迁移目录前应备份，并把原 Vault 文件一起复制到新目录。

1. 在工作台创建公司、部门或员工知识空间，系统创建对应目录。
2. 在目录内新增或编辑 `.md`。每 10 秒重新检查，工作台可手动“立即同步笔记”。根目录的说明文件和隐藏目录不会进入员工检索。
3. 在员工配置中勾选知识空间，并开启 `knowledge_search` / `knowledge_read` 工具。
4. 运行批准时固定每位员工可见的文档版本清单；检索覆盖这些版本的全部切片，后续修改不会改变已批准运行的引用。
5. 运行结果可手动“保存到知识库”，生成普通 Markdown。不会自动把未经检查的输出当成长期知识。

文档引用包括 ID、版本、内容 SHA256、切片和原 Markdown 行号。运行详情的“查看引用原文”可打开当时的切片，即使笔记后来改名、更新或归档；引用版本缺失时明确报错，不会替换成新版本。Wiki 链接、标签及原文件属性保持在文件中；检索支持中文/英文关键词和本地多语言语义检索，不提供图片 OCR、PDF/Office 解析、Wiki 链接自动遍历。

## 本地语义与混合检索

后端使用 Transformers.js 4.3.0 和固定修订的 `Xenova/multilingual-e5-small` q8 模型，CPU 推理，384 维向量存入 PostgreSQL/pgvector。首次准备需要 Python 3，在后端项目目录运行：

```sh
python3 scripts/install-embedding-model.py
```

脚本从 Hugging Face 下载约 136 MB 公开模型文件，并逐一核对 `services/embedding/model-lock.json` 中固定的 SHA256。默认目录 `.data/embedding-models`，可用 `EMBEDDING_MODEL_DIR` 指定其他绝对路径。资料和查询不会上传；运行时禁止远程模型下载。启用前和进程首次加载时检查文件哈希，依赖审计使用固定锁文件。

在知识库页点击“启用混合检索”，系统先验证模型能运行，再补建当前笔记的索引；每 10 秒同步后的新内容自动补建。界面显示已索引数量和错误，可手动重试。历史版本和本次专用资料在首次检索时按需索引，因此大批资料的第一次查询可能较慢。关闭混合检索后，交互查询和新批准运行使用关键词；已批准运行保持原来的模式和模型版本，模型缺失或版本不匹配时明确报错，不悄悄改用其他模型。

两路召回均先限定授权的文档版本：关键词使用中文/英文词项，语义使用精确余弦距离 Top-20，再以 Reciprocal Rank Fusion 合并，默认返回 6 个引用。输入文本加 `query:` / `passage:` 前缀，使用均值池化和归一化。长切片分为重叠窗口，并按实际 Token 数再次拆分，覆盖尾部内容；窗口向量平均后归一化。排名只表示相对匹配，不能证明资料适用或答案正确。

模型、修订、运行库和窗口算法共同构成索引版本。索引与历史引用进入加密备份；模型文件较大，不进入在线备份，换机器后须用安装脚本重新准备。旧版备份无向量表时可恢复并重新索引。

依据：[ONNX 模型说明](https://huggingface.co/Xenova/multilingual-e5-small)、[原模型前缀与池化说明](https://huggingface.co/intfloat/multilingual-e5-small)、[Transformers.js 本地文件设置](https://huggingface.co/docs/transformers.js/custom_usage)、[pgvector 距离查询](https://github.com/pgvector/pgvector)。模型原作者使用 MIT 许可；下载权重不提交到本项目 Git 仓库。

已索引笔记可选使用 `ad_document_id` 保持重命名后的身份，工作台生成的文件自动包含该属性。外部新笔记没有该属性时按路径追踪，改名会成为新文档。复制笔记时删除原 ID；把带 ID 的笔记移到另一个知识空间会被拒绝，不能靠修改 frontmatter 扩权。

删除或移出空间目录的文件会退出后续检索，旧版本和运行引用保留。工作台归档文档会移入 Vault `.trash`；归档整个知识空间保留文件但停止索引。文件冲突会报错并保留版本，需先同步后重新编辑。

## Windows 与 Mac 同步

Windows Obsidian 与 Mac 后端需要同一套 Markdown 文件。可选 Obsidian Sync（需要自己的账户/订阅）、Syncthing，或已有的文件同步方式；本版本不自动开通付费同步，也未配置用户 Windows 电脑。

参考 [Obsidian 官方跨设备同步说明](https://obsidian.md/help/sync-notes)。只同步 Vault 文件夹，不要同步 `.data` 上层目录，那里包含凭证和运行记录。同步目标需在 Mac 保持可离线读取；同一 Vault 使用一种同步方式，避免多套同步工具互相覆盖。

## 本次运行的资料范围

在“项目与方案 → 编辑方案”中配置，保存后产生新方案版本：

- 长期资料可选“全部已授权资料”，或只选择目录中的文档；选择模式下留空表示本次不使用长期资料。目录只包含方案员工获授权的文档，实际检索仍与每位员工的空间授权取交集。资料失效、归档或授权撤回时，批准接口会拒绝该选择。
- 本次专用资料可直接粘贴或导入 Markdown、TXT、CSV、JSON，最多 20 份，单份 50,000 字符、合计 250,000 字符。每份必须明确选择至少一名方案员工，并给该员工开启知识检索工具。二进制内容和其他文件格式不支持。
- 批准前可在项目页展开本次资料正文和接收员工名单；批准时固定长期文档版本和临时正文。临时资料保存于项目版本及运行快照，不写入 Obsidian 或全局检索索引；每个新运行使用独立引用 ID。检索只在获授权的输入中排序，不能用另一个运行或员工的切片 ID 越权读取。
- 模型重新规划不能替换用户指定的资料范围或临时正文；若它移除了资料接收员工，生成结果会被拒绝，原方案保留。修改本次资料后需要保存新版本并重新批准。恢复运行继续沿用原批准快照。
- 输入资料和运行引用随加密备份保存。输入随后被修改或移除，旧运行仍可查看当时引用。中间产物保存在各 Run 的隔离工作区与交付物目录，不自动成为长期知识；用户确认保存运行结果后才进入 Obsidian。

## 限制与备份

单份正文最多 250,000 字符，索引扫描文件最多 500 KB，每空间最多 1,000 份。新批准的运行保存紧凑的授权文档版本清单，不再截断为前 300 个切片或 160 KB。查询在全部授权历史版本中排序后返回至多 6 个切片；正文保存在数据库不可变版本中，包含在加密备份内。升级前已批准的运行继续使用原有冻结内容，不能为历史运行补充当时未保存的资料。文件符号链接不被索引。

工作台加密备份包含已登记 Markdown 文件、索引和历史引用，不包含 `.obsidian` 的个人界面配置、未登记空间文件或附件。完整 Vault 可另外做文件备份。恢复前的 Markdown 会保留在 `.trash/restore-*`；运行档案亦保留恢复前副本。
