# 使用已有 JJ 项目验证交付

当前实际运行在 JJ。Windows 浏览器通过 SSH 本机转发访问，不需要把业务数据库复制回 Windows。

## 打开网页

已有转发正常时，打开 <http://127.0.0.1:4312/>。若转发退出，在 Windows 终端运行并保持窗口打开：

```powershell
ssh -N -L 127.0.0.1:4312:127.0.0.1:4310 jj
```

若 JJ 服务需要启动，可用 SSH 执行 `systemctl --user start weiwu-jj.service`。查看状态使用 `systemctl --user status weiwu-jj.service`；不要对运行中的任务随意重启。

## 查看已完成成果

打开 [已有温度转换项目](http://127.0.0.1:4312/#run/d22f8757-a521-4781-a0de-32ebd58c3b52)。这是此前完成的交付样例；新步骤检查点的验收进度单列在下文。

1. “逐项验收证据”展开 QA 和经理两项，查看对应命令、来源运行和文件版本。
2. “恢复沿用的真实测试结果”展示原 QA 的 17/17 和 16/16；“真实测试结果”展示经理本轮复测。
3. “交付物”预览或下载 `README.md`、`cli.mjs`、`cli.test.mjs`、`delivery.test.mjs`。四份文件放在同一个空目录。
4. 安装支持的 Node.js 后，按原员工 README 运行：

```powershell
node cli.mjs 25
node --test cli.test.mjs
node --test delivery.test.mjs
```

预期换算输出 `{"celsius":25,"fahrenheit":77}`，测试分别 17/17、16/16。本轮实际在 Node 24.19.0 上验证，无第三方业务依赖。

## 自己创建或复验任务

通过需求对话生成方案，确认团队后，在“项目与方案”检查负责人、文件合同、预算和验证命令。复验现有成果时，用“文件与项目导入”选定原文件快照，选择复制到工作区，并授予所有文件/终端员工；不用手动写数据库。

任务合同中展开“逐项验收证据”，可启用检查：每条标准选用已列入 `verify` 的命令，填写预期退出码、可选完整输出或 Node 最低通过测试数。全部标准须有映射。历史项目未启用时不会自动补写通过结论。

批准运行后，网页显示员工申请的具体命令；核对再逐次批准。出现失败、费用待核对或超限时，查看原因，不要连续点完整重试。恢复使用原运行的“检查恢复条件 → 恢复未完成任务 → 确认恢复”，会保留完成节点和历史费用，未完成操作重新申请审批。

若旧未知费用需要保留，页面有明确选择，预留仍占用原额度；不代表未扣费或外部操作可重放。金额或调用数用尽时需重新规划，失败版本和账本仍保留。

## 检查正常工作状态和步骤保存

运行页的“员工运行状态”显示当前任务与工作、等待模型、等待工具或等待审批等阶段。停止后的状态会标为历史记录；它不能说明员工仍在后台运行。刷新页面只读取档案，不会重新调用模型。

展开“步骤检查点”可看到保存边界、事件序号、文件数和时间。现有边界包括执行工具前、工具结果返回后、一个工作循环结束，以及节点交接通过。只有内容文件和日志都完整保存，才会出现可恢复的检查点；保存成功不等于 QA 或经理验收通过。

需要核对更细时，点击“导出完整追溯”，或在“执行时间线”选择“全部原始事件”。核对 `runtime/status` 中的员工、任务、尝试编号与阶段，以及 `step/checkpoint` 的文件哈希和事件序号。相同状态的例行轮询不会反复写入，新尝试或阶段变化会留下记录。无需修改数据库。

对于带步骤检查点的 OpenShell 运行，恢复前在“恢复位置”选择“最新工作现场”或具体保存点，然后检查恢复条件并确认。恢复会创建关联的新运行并保留原运行；已完成节点不重跑，费用与未知操作记录不随旧文件版本回退。换选保存点后需要重新检查，不能沿用旧确认。

符合只读测试合同、文件版本和固定沙箱环境的结果，才会显示“已沿用测试证据”。文件、权限、验收要求或环境改变时需要重测；未知外部操作须先核对。不要仅凭员工回复中的“测试通过”判断成功，应查看“真实测试结果”、封存交接及经理结论。

2026-10-20 的工程验证和限制见[加固报告](validation/mvp-hardening-2026-10-20.md)。本轮实际网页选点恢复已验证文件哈希一致和开发不重跑；QA 最终交接、经理及符合条件的测试免重跑仍未完成。旧快照漏掉复用标记时不会自动升级历史授权；历史测试通过记录也不能补写为可继承证据。

[本轮验收报告](validation/delivery-acceptance-2026-10-10.md)列明成功、失败、费用和限制。

## 用工作记录沉淀知识并查看复用效果

“知识库”下方有“工作记录”。先为来源部门创建知识空间，选择已完成运行，查看交付版本、真实测试计数和效率，再点击“登记工作知识”。重复登记复用原文档，不会生成一堆副本。归档部门后来源节点隐藏，原运行、知识历史和关联 ID 保留。

在“部门与员工”给员工绑定该知识空间、开启知识检索与原文读取。以员工身份测试查询词，确认得到文档版本与行号。下次项目批准时固定知识版本；员工实际检索/读取会记入执行记录。知识提供经验，验收仍须重新执行实际测试。

效率表分别展示总耗时、扣除审批等待后的耗时、模型响应耗时之和、输入/输出/总 Token、真实发送次数及登记费用。同条件首次完整成功运行存在且用量已结清时，显示减少量和百分比；增加显示负值。恢复分段、不同原始文件或不同验收要求不计算节省。这里统计执行阶段，规划与需求费用在“用量与费用”另记；检索引用不等于因果收益证明。

档案限额属于应用准入保护：单次 64 MiB、总 1 GiB 后暂停新增模型调用与命令申请，保留已有检查点及账本。工作知识登记最多 500 份 / 8 MiB。当前不自动清理旧交付，也不是 OS 磁盘硬限额。
