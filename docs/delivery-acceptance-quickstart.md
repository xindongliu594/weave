# 使用已有 JJ 项目验证交付

当前实际运行在 JJ。Windows 浏览器通过 SSH 本机转发访问，不需要把业务数据库复制回 Windows。

## 打开网页

已有转发正常时，打开 <http://127.0.0.1:4312/>。若转发退出，在 Windows 终端运行并保持窗口打开：

```powershell
ssh -N -L 127.0.0.1:4312:127.0.0.1:4310 jj
```

若 JJ 服务需要启动，可用 SSH 执行 `systemctl --user start weiwu-jj.service`。查看状态使用 `systemctl --user status weiwu-jj.service`；不要对运行中的任务随意重启。

## 查看已完成成果

打开 [本轮完成运行](http://127.0.0.1:4312/#run/d22f8757-a521-4781-a0de-32ebd58c3b52)。

1. “逐项验收证据”展开 QA 和经理两项，查看对应命令、来源运行和文件版本。
2. “恢复沿用的真实测试结果”展示原 QA 的 17/17 和 16/16；“真实测试结果”展示经理本轮复测。
3. “交付物”预览或下载 `README.md`、`cli.mjs`、`cli.test.mjs`、`delivery.test.mjs`。四份文件放在同一个空目录。
4. 安装支持的 Node.js 后，按原员工 README 运行：

```powershell
node cli.mjs 25
node --test cli.test.mjs
node --test delivery.test.mjs
```

预期换算输出 `{"celsius":25,"fahrenheit":77}`，测试分别 17/17、16/16。本轮实际在 Node 24.19.0 上验证，无第三方业务依赖。

## 自己创建或复验任务

通过需求对话生成方案，确认团队后，在“项目与方案”检查负责人、文件合同、预算和验证命令。复验现有成果时，用“文件与项目导入”选定原文件快照，选择复制到工作区，并授予所有文件/终端员工；不用手动写数据库。

任务合同中展开“逐项验收证据”，可启用检查：每条标准选用已列入 `verify` 的命令，填写预期退出码、可选完整输出或 Node 最低通过测试数。全部标准须有映射。历史项目未启用时不会自动补写通过结论。

批准运行后，网页显示员工申请的具体命令；核对再逐次批准。出现失败、费用待核对或超限时，查看原因，不要连续点完整重试。恢复使用原运行的“检查恢复条件 → 恢复未完成任务 → 确认恢复”，会保留完成节点和历史费用，未完成操作重新申请审批。

若旧未知费用需要保留，页面有明确选择，预留仍占用原额度；不代表未扣费或外部操作可重放。金额或调用数用尽时需重新规划，失败版本和账本仍保留。
