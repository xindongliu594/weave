# 模拟产品流程验证

2026-09-30，在 Linux 测试环境中，通过真实 Express API、持久队列、ProductDshRuntime、DSH/AgentTeams、审批表、文件合同、用量与导出接口运行了一轮产品流程。

## 复验

```bash
npm ci
npm --prefix services/agent-runtime ci
npm run test:integration
```

不需要模型 API key、外部中转站、Docker 或已安装的 PostgreSQL。测试会启动带 pgvector 的临时 PGlite 数据库和本地模拟 HTTP 模型服务，创建临时目录与独立 schema，结束后清理。模型的文本连接和工具往返证据通过真实 API 生成，不直接伪造可用状态。可使用 `npm run test:integration -- tests/product-flow.test.ts` 单独复验文件流程。

默认执行 API、工具能力、文件流程三个测试文件，14 项全部通过；另有 39 项非 Docker 运行时测试、14 项纯规则测试通过，TypeScript/Vite 构建通过。机器可读证据见 [simulated-product-flow-20260930.json](test-evidence/simulated-product-flow-20260930.json)。

## 观察结果

| 场景 | 实际结果 |
| --- | --- |
| 批准方案 → 队列 → 产出 → 命令审批 → 独立审查 → 文件下载与计费 | completed；两个宿主验收记录；审批前命令执行次数为 0，批准后为 1；报告为 2 单、4095 分；产出与审查使用不同 session；用量对应已结算预留 |
| 声称完成但没有声明的输出文件 | 没有验收记录；下游模型请求与命令执行均为 0 |
| 模型声称验证通过但未实际运行命令 | 没有验收记录；没有工具审批；下游模型请求为 0 |
| 宿主验收后输入文件被改动 | failed；VERSION_MISMATCH；下游模型请求为 0 |
| 等待命令审批时取消 | cancelled；审批状态 cancelled；命令未执行；旧审批返回 409 |

这些场景使用既有固定订单报告作为预期值。模型动作脚本只提供输入，宿主与 API 决定审批、验收、调度、终止和结算结果。

## 本轮修复

1. 队列已经持有事务连接时，读取设置复用该连接，避免再次等待连接池。
2. 工具能力测试在写入测试记录并提交事务后立即释放连接，避免在等待两次模型回复期间占用连接，以及结束记录再次等待同一连接池。
3. 审批与运行时分别打开同一日志时，原实现使用各自缓存的序号，造成重复序号，任务完成但日志不完整。追加现在同步核对当前日志、分配下一序号，并从当前记录核对 sourceKey；旧句柄也拒绝向已损坏日志追加。API 文件流程和交错句柄回归测试覆盖了此问题。

日志追加会读取当前完整档案，这是正确性优先的实现；大型档案的写入性能仍需测量。回归验证覆盖同一个 Node 进程中的多个句柄与随后新进程读取，未验证不同进程同时写入同一日志的互斥。

## 测试替身与验收边界

- 模型回复来自本地脚本；证明协议与调度可以运行，不证明真实模型能理解需求或生成合格代码。
- 文件、哈希、合同和下载使用真实临时文件；Docker 镜像就绪检查与执行器是测试替身。执行器只允许两个固定文件和一个固定 JSON 校验，不运行模型提供的 shell/code，不验证 Docker 权限、隔离或清理。
- PGlite 使用 PostgreSQL 的 WASM 运行环境与 pgvector，但只有一个后端。专用测试 preload 将产品连接池限制为一个连接，其他产品入口不受影响。真实 PostgreSQL 多连接、行锁竞争、多 worker 租约、并发恢复、跨进程档案写入均不在本轮验收范围；不能用这条命令替代 `npm test` 与 Docker 测试。
- 浏览器 UI、Mac 部署、真实中转站、真实模型与本地 embedding 模型仍需各自验收。预设测试不依赖这些组件，也没有支付模型费用。

这轮把此前因数据库缺失而无法运行的部分 API 流程补上，并发现了单层测试没有触发的连接与日志问题。真实 PostgreSQL、Docker、模型与部署验证仍须保留。
