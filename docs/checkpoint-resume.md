# DAG 断点恢复与工作上下文

更新：2026-10-02。

## 使用方式

运行失败、取消或服务中断后，在运行详情点击「恢复未完成任务」。系统创建新的运行档案，保留原批准方案的完整任务图和任务 ID；已核验完成的节点恢复为 completed，未完成节点获得新 attempt 后重新执行。开发完成、独立测试中断时，不再因为审查引用开发节点而强制完整重试。

恢复后的运行页可展开「断点恢复」，查看沿用的任务、上次问题、带入文件和原运行链接。「完整重试」仍从原批准的完整方案开始，不继承检查点、工作摘要或旧工作目录。

## 恢复什么

批准快照固定需求、任务合同、员工权限、知识版本和项目预算。`recovery` 清单另外保存：

- 已完成任务的 attempt、输出、审查结论及质量字段；宿主文件封存记录仍保存在 `handoffCheckpoints`。
- 每个节点的上次状态、结果摘要、最近工作说明、已有上下文整理摘要、最近命令回执、错误和知识切片引用。整理此清单不额外调用模型。
- 工作文件路径、大小和 SHA256，区分已验收交付、固定输入和未验收中间成果。恢复到新目录后、首次模型执行前，再核对清单哈希。
- 原运行 ID；完整会话、工具输出、知识引用和命令证据保留在原始档案中。

模型启动时只加载当前节点的摘要、部分前置交付和资料索引，长度按上下文字节预算限制。只读 `recovery_read` 支持逐页读取完整历史和长文本。连续恢复时可追溯到更早的父运行，而不是只记得最后一次中断。

员工只可读取当前任务的历史与前置节点的共享交付。前置节点的私有会话、内部知识检索正文不直接开放；知识正文继续走原有按员工授权的版本检索。历史内容是资料，不能增加权限、修改合同或充当新的审批。模型摘要不是任务完成的证据。

## 调度与安全边界

原生团队仍在 staged 状态时，宿主通过锁定的持久化层恢复已完成状态，再批准调度。这个恢复入口不作为模型工具提供。依赖边、`reviewedTaskId` 和 `sourceTaskId` 保留；已完成节点不重新调用模型。节点验收完成后立即保存团队检查点，停止时再保存最终状态。

未完成节点会重新获取任务、检查现有文件并执行本次验证；上一次运行的测试回执不能冒充本次验证。旧审批不重放，未知操作结果与未知模型费用仍须核对。费用、调用次数、返工次数继续累计；已完成节点不会因为不再需要使用的任务额度耗尽而阻止其他节点恢复。

文件修改导致验收哈希失效、档案损坏、知识版本缺失或授权失效时拒绝不安全的恢复，不把缺失资料静默替换成新资料。

## 已验证与暂不支持

回归验证使用真实 API、持久化档案、队列和 DSH 员工宿主，模型由固定 HTTP 响应提供。覆盖开发完成后测试中断、关闭并重新创建 API/协调器后恢复、连续两次中断、未验收文件保留、按需读取历史、只调度剩余节点、已独立通过的返工链恢复。另有文件篡改拒绝、历史分页、知识隔离和预算准入检查。

这是**任务节点级恢复**，不是模型 token 或命令执行中间位置的恢复。服务重启会识别中断，但不会未经用户选择自动重放执行。尚未独立验收完成的动态修复/复验链仍保持原来的阻止恢复规则，可检查后完整重试；本次没有把这类中间图压平为已完成节点。未宣称完成真实模型连续多日运行或任意操作的恰好一次执行验证。
