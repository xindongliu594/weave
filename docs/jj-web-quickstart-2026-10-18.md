# 为伍网页使用说明

Windows 负责打开网页；部门、项目、数据库、交付文件与员工工具在 JJ 运行。模型推理使用后端已保存的 API。网页不会自动获得 Windows 文件或桌面操作权限。

## 打开工作台

在本项目 PowerShell 执行：

```powershell
.\scripts\deployment\connect-jj.ps1
```

打开脚本输出的地址，默认 `http://127.0.0.1:4312/`。新版脚本使用 OpenSSH 原生压缩，仍只监听本机回环地址。已有隧道时直接使用，脚本遇到占用端口会保留现有进程；需要另一入口可指定 `-LocalPort 4313`。

首次加载需要传输网页和历史资料。读取请求最多等待 30 秒；失败后检查 JJ 是否开机联网，重新读取或刷新页面。关闭网页、断开 Windows 隧道不会清空 JJ 的数据，也不等于停止正在执行的员工。

## 使用现成插件完成任务

1. 打开“浏览器与 MCP”，查看“原生插件工具”。当前已安装并启用 `@huiliyi37/dsh-office 0.2.4`，这里显示来源与版本。
2. 在“部门与员工”核对员工的工具授权。写 Word 的员工需要 `office · docx_create` 和 `office · docx_read`；只核对内容的 QA/经理通常只需要 `docx_read`，以及输出验收报告所需的文件工具。插件启用不会自动给所有员工授权。
3. 新部门从“需求组建”开始，持续补充目标、资料和验收标准；确认团队方案后保存部门和项目。已有部门从工作台录入新需求。
4. 核对项目的工具范围、模型、预算和输出文件，选择 **OpenShell 隔离执行设备**，确认方案后执行。员工在获授权目录里自行检索工具并按需调用。
5. 在“执行记录”查看节点、员工状态、费用、审批与交接。普通用户不需要修改数据库；如有审批，只批准你理解且属于任务范围的操作。
6. 完成后检查 QA 与经理报告，再从“交付物”下载文件。Word 用 Word/WPS 打开；本轮验证了文档格式与正文，未做桌面像素级版式验收。

可直接查看已有[办公插件验收项目](http://127.0.0.1:4312/#run/c6516254-6ab0-44c3-88f8-f9e86ac81592)：`report.docx`、`qa.json`、`acceptance.json` 均由员工生成。三条巡检内容为虚构资料，用于验证工具能力，没有实际巡检网站。该项目已完成，查看或下载无需再次执行或调用模型。

## 查看失败和恢复

读取网页失败：使用“重新读取运行记录”，只读原档案。不要把“运行追溯验证”“完整重试”当成刷新按钮。

员工执行中断：打开原运行，查看原因及“检查恢复条件”；核对原方案、完成节点、剩余额度与未知操作，再恢复未完成任务。完整重试会重新执行，可能重复操作并产生费用。网络中断不证明外部请求未执行，结果未知的操作不能盲目重放。

事件采用分页显示，点击“加载后续事件”继续查看；“导出完整追溯”保留全部原始记录。

## 当前边界

- 已接入经过核对的文件工具型插件。网页可启用、停用和授权；**市场搜索与一键安装尚未实现**，新增安装仍需管理员使用既有 DSH 安装流程并核对沙箱兼容性。
- Skill、MCP 沿用各自标准加载和权限；后台服务型与原生 DSH 网页型插件不在本次通过范围。
- 停用插件会阻止后续调用；历史快照绑定原版本，恢复不会自动换新版。
- JJ 的业务数据在 `/home/jj/.local/share/weiwu/data/pilot`。清理、备份与停止恢复说明见[已有使用指南](deployment-jj-quickstart-2026-10-09.md)，其中旧试点预算数字是历史授权，当前以项目方案与后续明确授权为准。
- 远程网络仍可能抖动；本轮没有验收连续 24 小时运行、设备休眠或断电恢复。
