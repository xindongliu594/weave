## 功能

部门与员工：内置部门、岗位模板，可保存自己的模板；岗位职责、系统约束、输出要求与当前任务目标分开。修改职责保留角色版本，部门归档可恢复。需求可生成模板预览后保存新部门和草案；调用真实模型的生成按钮明确标注费用。

执行：批准的角色、任务 DAG、模型路由、知识和授权生成运行快照，模型不能自行改写组织与任务范围。支持已配置备用模型、最大模型调用次数、上下文字节限制、执行期限和预算。全自动仅允许门槛内的文本/知识任务；越界拒绝批准。其他模式仍需用户审阅方案。并发限制约束同时进行的模型/工具操作，不限制 DSH 驻留成员个数。

工具：文件操作仅在每次运行的 Docker 工作区，禁止宿主目录挂载及联网；限制内存、CPU、进程数、文件体积。终端和测试命令每次都需在执行页审批。产物收集到运行档案，可预览文本和下载。

恢复：队列持久化，部门同一时间只运行一个任务，工作进程维护租约。中断标记后不会自动重放，用户可从已完成任务检查点恢复，或完整重试；未完成操作可能重复。每次恢复生成新 Run，保留来源、预算和先前交付物。

知识：[Obsidian 接入说明](obsidian.md)。资料按公司、部门、员工分空间，检索先过滤授权；运行冻结版本，引用含文档 ID、版本、哈希、切片和文件行号。运行结果可手动沉淀到 Vault。

追溯：运行内查看角色/任务提示词、原始及实际发送的模型上下文、工具参数结果、审批、任务依赖状态、知识引用和费用；可导出完整档案。截断或损坏日志标为不完整，不能伪装成成功。

设置：自动运行门槛、执行准入每日预算、跨部门运行数，环境诊断和镜像准备，加密备份恢复。备份含已登记 Markdown、DB、凭证密钥和运行档案；离线密码丢失无法恢复。每日执行准入检查已发生用量和队列预留；规划调用另按单次与项目上限检查。
