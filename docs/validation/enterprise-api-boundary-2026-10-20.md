# 企业 API 边界：本地验证记录

2026-10-20。本轮仅完成 A1 Task2 的后端和本机客户端接线，企业登录网页、部门级资源授权与部署验收另有后续任务。

复用已固定的 OIDC 协议、Express 会话与现有设备凭证。企业模式的 142 条业务路由进入明确权限目录，当前人类业务操作仅管理员可用；普通成员无隐式业务读取权限。设备凭证仅能调用四个设备接口，不能注册新设备、读取业务或成为人类管理员。授权、当前会话世代与 CSRF 检查先于幂等缓存；幂等键按主体隔离。未分类路径和不支持的注册语法会被拒绝。

应用启动有明确的 identity ready/failed 状态；关闭后台业务和关闭身份服务分别处理。企业本机执行器复用已批准配置，首次凭证探测失败不报告连接成功，也不会先轮换凭据再检查批准。原 legacy-local 仅本机的入口保留。

首次审查发现并修复路由登记遗漏、初始设备拒绝仍报告就绪、配置先轮换后核准等问题。二次审查又发现部分 HTTP 方法/中间件参数未纳入清单，以及测试错误地要求收据只能传一次。最终独立复审：

- 路由、来源与跨站限制 10/10；本机启动和已批准配置 10/10。
- 实际 createApp 隔离集成 1/1，覆盖全部 142 条业务路由、持久会话撤销、CSRF 与主体缓存、设备接口、启动关闭及最小健康探测。另有主体幂等回归 2/2。
- 对实际登记检查器作 94 个只改内存源码的有效变异：35 种 HTTP 方法分别放到 app/router、21 个可达文件各新增中间件，以及第三参数/spread/array 情形，均被拒绝；变异前后原始清单均通过。

证据保存在 .superpowers/sdd/2026-10-20-oidc-api-integration/task-2-fix2-independent-review.md 及对应日志。临时 PGlite、回环 HTTP 和测试会话不能证明真实 PostgreSQL 并发、浏览器完整登录或 Linux/OpenShell 客户端启动；这些门禁仍未完成。登记检查是有限源码约束，不能防御任意恶意开发者修改 JavaScript。

本模块经独立复审 PASS。本轮未修改 JJ 生产服务、未激活企业模式、未调用真实模型或提高预算；B2 成果提交的工作区改动不包含在此模块提交中。
