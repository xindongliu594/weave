本轮修复了复杂草案在首个字段错误处停止诊断的问题。现在保留原来的严格拒绝，同时把可独立判断的文件权限、验收映射等问题交给现有 `previousDraftIssue` 纠正入口。**Windows 与 JJ 各通过 85 项单元、44 项 API 检查；类型检查和构建通过。本轮新增付费模型调用为 0。**

## 原因与改动

上一轮真实的“带返工审查”草案把费用和 Token 字段放入 `handoff`，严格解析因此拒绝。它还存在只读员工被要求写文件、验收命令映射不完整、测试最低数量缺失，但这些问题当时未一起返回。

本轮复用已安装的 Zod 4.1.5、现有计划校验和对话反馈接口，没有新增依赖或更换运行时。诊断副本仅排除无效交接章节，检查与之无关的任务字段；副本不返回、不保存，也不能生成有效预览。现有团队身份仍由原授权与版本解析流程处理。完整候选仍须通过原严格校验。

- 复用办公规划中已有的文件写入权限说明，补充到终端任务规划中。
- 明确交接章节只包含 `sections`，费用及 Token 字段属于任务本身。
- 收集可独立判断的问题，去掉重复报告，反馈限制在现有 4000 字符输入约束内。
- 保留有效候选、显式确认、原预算、原权限和调用行为；不增加自动重试。

调研依据与未选方案见[实施计划](../superpowers/plans/2026-10-19-organization-draft-feedback.md)。已有结构化输出工具不能替代本项目的跨字段权限与验收校验；本轮没有为尚未核实的 Go 能力添加请求选项。
