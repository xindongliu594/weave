## 本轮变更

- 根工程与 runtime 的 npm 名称改为 `weave`、`weave-runtime`，同步各自 lock 文件；README、网页标题/品牌和浏览器 MCP 客户端标识使用 Weave。
- 保留既有数据库、浏览器存储 key、备份格式，以及桌面包身份、appId 和产品名。它们涉及旧数据和 Electron `userData` 兼容；本轮没有迁移数据，也没有改动生产执行或权限守卫。
- 纳入此前未跟踪的设计、调研、验收摘要及源码清单，包括七维评测设计。评测设计仍是设计，不能据此宣称 160 个案例已经实现或通过。
- 29 份依赖本地私有夹具的历史测试与 6 份一次性 Cortex 脚本逐字节归档到 [历史源码目录](historical-sources/README.md)，不进入自动测试发现；原路径和 SHA-256 见该目录 manifest。
- 个人客户端代理脚本、三份完整原始模型/运行 JSON 与上述源码原件保留本地，不纳入本次提交。凭据、数据库、私人简历与 `.private` 工作资料不入库。历史文档中的部分原始证据链接仅在原验收环境可用。

## 合并前已知问题

- `tests/api.test.ts` 中旧规划授权测试预期保存无效知识授权后才在批准时拒绝，当前保存接口已提前拒绝；旧追溯导出用例也与当前接口返回/授权契约不一致。需要按当前安全合同更新夹具，不能放宽生产校验来满足旧预期。
- `services/agent-runtime/status-lifecycle.test.mjs` 的冷恢复取消/到期夹具未处理现有 `RUNTIME_WRITER_DRAIN_UNPROVEN` 契约；清理拒绝后跳过测试服务器关闭，导致测试不能退出。独立单项可复现。现有 writer-drain 守卫必须保留；应明确断言未证明状态，并保证夹具清理总能执行。
- 更广检查还发现备份/公司能力等旧夹具失败，以及依赖本地嵌入资源或真实数据库语义的检查未满足。尚未逐项区分为环境、夹具和产品问题，不宣称它们均无影响。

本轮没有付费模型调用，没有提高预算或放宽权限，没有重新执行员工项目。提交快照不代表上述失败已修复，也不代表 MVP 的全部验收完成；是否先将此快照合并到 `main`，须明确保留这些验证限制。
