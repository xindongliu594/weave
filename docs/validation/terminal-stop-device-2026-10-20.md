# 停止维护的取消与超时前置能力

本片仅修改现有设备执行器及其测试，独立复审PASS。项目最终收尾、网页核对入口与物理JJ验收尚未接通，task profile继续关闭。

复用原维护队列，排队请求取消后永久跳过，避免稍后才执行停止。已经开始的请求等待实际结果，不能用超时伪造完成。停止与原ID核对共用同一个AbortSignal；可信派发回调返回后，再同步检查取消、授权、配置和完整journal，然后才能保存唯一意图、派发一次停止。提供版本化deadline能力声明，供后续API预检固定。

本机CLI取消时先请求结束进程，等原子进程close后再返回；失败kill或没有close不能冒充settled。远端结果仍未知时保留原意图、未知状态和容量预留，不重放。能力声明表示支持共享取消协议，不是任意操作系统或自定义transport必能按硬实时期限终结的证明。

验证：新增13项中，修前11项实际行为失败、2项原行为/真实进程特征通过；修后13/13。三个原设备相关文件首次在受限环境67/68，唯一失败为既有symlink权限EPERM；相同窄命令在授权环境68/68、0跳过、退出0，耗时12.113秒。root另执行两个文件`node --check`退出0。初次测试清理gate挂起的中断日志单列保留，没有充作有效业务RED。
