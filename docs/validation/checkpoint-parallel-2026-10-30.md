# Checkpoint 并行收口：写入保护、核账及主流程回归

工作从 2026-10-29 持续到 2026-10-30。基线为 `417b46e` 加此前保留的本地修改。本批与另一对话的成员工作台、OpenTelemetry 导出和 Promptfoo 评测分开归属；这些功能不计入本报告成果。没有提交、推送或部署，没有真实模型调用或新增项目费用。

## 实际改动

沿用已安装的 DSH 持久化、`fs-native-extensions@1.5.1`、现有 archive writer、PostgreSQL 收据事务及 Node 测试入口，没有新增锁引擎、恢复引擎或插件框架。

1. **核账生产者完整排空。** 运行收据先无锁发现真实 run，取得同一应用的 writer，再在原事务内核对身份。保护覆盖 claim、原账单请求、结算和保存。只有当前原事务未派发 COMMIT 且 ROLLBACK 确认完成，普通拒绝才在作用域外返回；提交/回滚不明仍保留阻断，不因补一次 save 而丢失失败事实。无 run 的规划收据沿用原 SQL 共享费用门禁。
2. **规划诊断与目录恢复分离。** 新诊断写到 `resolve(TRACE_ROOT)+'.planning-output-diagnostics'`，保留旧根内诊断原件；根目录被交换时不再重新创建它。拒绝目标目录为链接或非目录。此位置属于故障诊断，未自动扩大运行/交付备份的收集范围。
3. **检查点首个物理变更受保护。** 删除 `commitStepCheckpoint` 提前创建对象目录的重复代码，由现有受保护的对象存储入口创建并同步目录。未持锁请求在任何对象目录变更前拒绝；合法保存与独立离线场景保持。
4. **可运行的主流程回归。** 原 19 个场景拆为六组 4/7/3/1/3/1，保留测试体与断言。旧 runner 路径展开全部六组；直接执行旧测试文件只运行本机设备四例。每组统一 180 秒，未提高产品时限或调用额度。退出码合并保留之前的超时 124。独立审查发现 schema 时间戳碰撞，已改 UUID，并仅清理本进程成功创建的数据。
5. **物理故障证据。** create、append、SHA 对象各注入 write/fsync 失败，共六例；真实生产绑定执行部分写入或完整写后失败，上层 catch 和 finish 后另一个真实进程仍不能取得 source。持有者实际退出后锁才由操作系统释放，文件未重放。这是模拟 EIO 的协议证据，不是断电耐久性证明。

## 失败与审查

- 受限环境的临时目录/IPC/loopback EACCES 单列为环境或脚手架失败，不充当产品 RED。原生普通 Windows 重试后取得有效结果。
- 核账修复原始 RED 复现了原 COMMIT 尾部尚未结束却可取得 source、writer 等待之前已开始 claim、提交未知丢失占用等问题。修复后定向结果通过。
- 初轮费用回归 11/12：旧夹具在登记根上无作用域建档。只修夹具为真实 writer，结束后打开新句柄 append，最后费用12/12与规划8/8同命令exit0。旧失败保留。
- 产品首次四组仍有一组超180秒；按真实耗时继续拆成六组，没有删除场景或提高统一时限。
- Checkpoint 入口新测试先真实失败：scope错误发生时目录已经出现；删除重复mkdir后10项通过。首次自动审批超时未执行，不算RED；允许的重试正常执行。
- B、C、D、E和最后F/整合均接受独立只读审查。C发现的schema碰撞已修复并复审；D报告的过时失败状态已更新。最后没有待处理Critical/Important。

核账锁存阻止source，并不代表永久禁止其他shared writer。即时重复查询只验证原30秒claim窗口；之后遵循原次数、暂停与claim规则的账单GET仍可查询，不重放模型或业务写操作。
