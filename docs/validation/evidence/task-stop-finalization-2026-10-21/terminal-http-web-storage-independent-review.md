## P2 — unreadable archives bypass the protected SQL maintenance fallback

Location: `apps/api/src/app.ts:536-544`, especially the unguarded `readRun(traceRoot,id)` at line 538.

The new detail integration correctly returns pending/unverified maintenance when `readRun` returns null (for example, a missing snapshot), but it does not handle archive read exceptions. A malformed existing `snapshot.json` throws during JSON parsing. A missing plain journal without a usable compressed archive, malformed archive metadata, checksum failure or unreadable archive file also throws from `readJournal`. Because this read occurs before the SQL row query and before `readTaskStopMaintenance`, the entire detail request fails instead of showing the known SQL run with protected pending/unverified maintenance. After an original-ID observation fails for that same unreadable archive, the UI's mandatory GET refresh therefore cannot display the protected fact either.

The supplied actual-app test only renames `snapshot.json`, exercising readRun's null return. It does not cover the throwing unreadable-archive paths. The frozen projection contract requires unavailable original history to fail observation closed and remain visibly unverified; an inaccessible detail page does not deliver that state.

Smallest correction: handle the archive read failure locally in this GET, continue through the existing known-SQL-run fallback, feed unavailable history to the projection, and explicitly mark the archive as unavailable/incomplete. Preserve a 404 when neither a readable archive nor SQL run exists. Do not expose raw filesystem/JSON/archive errors or authorize reconciliation/recovery from this fallback. No generic archive repair mechanism or new state store is needed.

Minimum REDs: with an existing SQL task run/marker, (1) replace the snapshot with malformed JSON, and (2) retain the snapshot but make the journal/archived-journal unreadable or invalid. GET `/api/runs/:id` should still return that run with pending/unverified maintenance, `canReconcile:false`, and visibly incomplete archive metadata, rather than 500. Original marker/provider effects must remain unchanged. These are source-derived expected failures; this reviewer did not execute tests.
