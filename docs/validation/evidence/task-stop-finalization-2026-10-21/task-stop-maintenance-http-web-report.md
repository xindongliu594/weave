The router is mounted after existing admin authentication/CSRF and accepts only the strict original full key, sandbox identity, partial revision and stop ID. It calls only the source-owned `TaskAcceptedStopLifecycle.reconcileExact(input,signal)`; it never calls a new stop/prepare/enqueue/start/exec/delete method or creates a queue. Successful observation re-reads the SQL projection and returns `{maintenance,replayed:false}`. Safe allowlisted 409 codes/static messages replace private provider/SQL errors. Exactly the POST original-stop reconciliation path bypasses generic response caching; ordinary mutation caches remain unchanged.

GET run detail includes `taskStopMaintenance` with an archive and in the existing SQL-row/missing-archive fallback. Summary events include the two maintenance observations. The shared web component validates strict DTOs before rendering actionable scopes and rejects a projection belonging to another run. Business status stays visible beside maintenance status; task/attempt/generation, exact sandbox ID and the partial workspace revision are displayed. NULL/no-intent, stopped and unverified scopes expose no stop action. Only an existing validated pending intent exposes “核对原停止结果”. File/disk retention is explicit; confirmed running-slot stop does not claim disk reclamation.

The component's own single in-flight lock is the actual click path, tested through its extracted small async handler. It uses the existing `api()` helper for authorization/CSRF, has no retry/cache/local stop facts, stays locked through the fresh GET callback, refreshes after success or rejection, and does not publish local success from a response payload. Cleanup deactivates the handler. Run detail refresh applies only to the original run ID; the component refuses stale cross-run projections. Task storage rows use full key plus sandbox ID, or the unverified display key, and omit the old run-level inspect/retire buttons. Legacy storage controls remain unchanged. The two maintenance timeline events have Chinese labels.
