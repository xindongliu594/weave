# 首页员工可用模型选择验证

2026-10-05。首页此前只能选择负责组建的模型，未设置 `allowedModelIds` 时后端目录仅包含它，用户无法正常请求 Astra 规划、Luna 开发、Sol 独立测试的团队。现已在「组建设置」加入「员工与后续规划可用模型」复选框。

- 旧草稿缺少列表时，只隐式允许当前组建模型；不写入整个模型目录。由默认 Luna 切换到 Astra 时，只显式允许 Astra，Luna/Sol 仍需明确勾选。
- 已有显式允许列表在切换组建模型时保留，加入新的组建模型且去重；当前组建模型不可取消。若旧显式列表遗漏组建模型，页面提示并禁止发送，允许用户勾选修复。
- 仅可用模型可新增勾选。已有不可用模型的授权不会被其它勾选操作静默删除。请求结果不明时模型设置禁用，保留原请求恢复入口。
- 预算、费用限额、工具、知识空间、本机执行目标保持原值。新增选择不调用模型、不保存正式团队、不批准执行；修改设置仍需发送更新方案，再明确确认。

实现：[OrganizationChat.tsx](../../apps/web/src/OrganizationChat.tsx)。新增回归：[organization-allowed-models-ui.test.ts](../../tests/organization-allowed-models-ui.test.ts)。真实输出：[验证日志](organization-allowed-models-ui-2026-10-05.txt)。新回归 8/8，连同组织草稿、任务预算和规划候选回归共 32/32，失败/跳过均 0；`npx tsc --noEmit` 退出 0，相关 diff 无空白错误。

测试使用既有 Vite 的 SSR 加载真实带 CSS 的组件，`middlewareMode`、无 HTTP 监听、禁用 HMR/文件监听；操作实际复选框/选择器回调并渲染首页。Node 中的测试 sessionStorage 独立且复原。未访问原数据库、付费模型或浏览器，未启动/停止产品服务。截图及真实组建流程由主代理另行验证，此报告不替代模型验收。

网页定位：`getByLabel('负责组建的模型')`；打开「组建设置」后 `getByLabel('允许员工与后续规划使用：gpt-6-luna')` / `gpt-6-sol`；Astra 选中后标「负责组建，必选」。每新项目预算需显式填写 $5。首页组建请求单次输出仍为 4000 Token，实际 Astra 输出报价 $50/百万时，输出预留已 $0.20，输入另计；默认每轮 $0.10 不足。所有对话费用需纳入本轮总额监控。

确认后的最短配置路径：「查看执行方案 → 编辑方案 → 项目执行策略 → 文件与命令执行位置」核实本机设备；员工「岗位模板、输出规范与知识授权 → 授权知识库」，并分别授权员工知识工具与策略知识空间，再保存和批准。首页后端仍将允许知识空间设为 []，本次没有扩展该权限。第二份项目从「新需求」开始，避免更新第一份团队。
