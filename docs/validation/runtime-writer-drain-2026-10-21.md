## 发现与修复

- 限时 `drain()` 可能先返回，但原请求仍在审批、响应处理或费用回填中。新增稳定的 `writerDrained`，永久停止新请求后，等待所有原请求真正结束。
- 已验收的业务结果与资源清理分开记录。关闭超时不把交付改成失败，也不提前释放占用；原清理失败则保留明确的待核对状态，阻止新任务复用现场。
- 固定 Cordis 版本会将部分插件清理异常写入日志，外层 `dispose()` 却正常返回。实际原生插件测试复现后，复用每个 Context 的结构化日志 exporter，配合原始销毁 Promise 识别清理失败；没有修改或升级上游依赖。
- 原生启动已进入、却没有交还完整 handle 时，不假定它已停止。无法证明结束的尾部保持 `RUNTIME_WRITER_DRAIN_UNPROVEN`；已知清理失败使用 `RUNTIME_WRITER_DRAIN_FAILED`。
- 旧 Docker 执行器按每次容器代次保存原关闭 Promise，避免重复关闭、遗失关闭结果，同时保留连续终端命令的正常行为。
- 协调器区分执行、排空、排空失败。业务终态落库后，不再续写执行租约或错误取消已完成任务；服务关闭等待原尾部，失败时不会继续关闭数据库并宣称正常退出。

保留原 DSH 调度、持久化、预算、权限、未知费用和交付验收规则。本批没有接入原生写入锁，没有签发恢复来源批准。
