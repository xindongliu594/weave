本轮完成已确认的提示/合同不一致修复，Windows 和 JJ 各通过 **87 项相关单元 + 42 项 API 隔离回归**。类型检查和前端构建通过，独立代码审查无待修事项。**真实模型质量尚未复测，历史真实规划仍为 0/7；七种新模板仍仅预览。**

## 修复内容

1. 复用安装版本 Zod 4.1.5 的 JSON Schema 转换器，仅在发给模型的生成格式中去除新部门每日预算、员工来源、备用模型、知识空间、浏览器和 MCP 配置。V2 对话只说明 target 等 V2 字段；旧对话保留 department 格式。原持久化 schema、经理唯一性、员工 ID 去重和权限校验不改。
2. 有返工的合同示例改为“开发 → 独立审查 → QA → 经理”。审查与 QA 可由同一独立员工分两节点承担；审查与经理都明确要求结构化证据。旧零返工示例保留。补清文件读写权限、交付要求与检查者、零基验收索引、交叉批评配对及固定分片输入。
3. 失败 API 响应增加安全的 `outputDiagnostic`：原因、JSON 错误位置、供应方停止原因（若有）、原文 SHA256 和字节数。复用已有诊断组件，不返回原始方案；下一轮 `previousDraftIssue` 格式不改，不引入额外模型请求。

调研及选择见 [修复计划](../superpowers/plans/2026-10-19-orchestration-planning-repair.md)。没有安装新的 JSON 修补器、模型 SDK 或编排引擎。
