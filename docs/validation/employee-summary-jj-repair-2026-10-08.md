# JJ 真实小任务发现的上下文问题

日期：2026-10-08。员工模型为 OpenCode Go / DeepSeek V4.1 Flash，真实业务运行不是固定响应测试。

## 发现与修复

1. Run `f6690108-e1ec-4251-bdb3-0c256fa82349` 写入 CLI/README 后，摘要输出恰好1024 Token并截断。该调用 reasoningTokens=0，与余额或模型思考无关。我们在 DSH 上额外设置的1024帽低于任务已批准的2048；显式策略与通用初始化现在均取消额外帽。最终请求仍由批准route/task及共享费用、调用次数控制，截断摘要不被采纳。
2. Run `a4ab3c71-70c6-43fa-bc8d-fbdda52f5a52` 完成真实语法检查，1596/1981 Token的摘要成功提交；随后总估算11721仍超过11200软线而停止。DSH 自带自动处理把软压力视为警告，我们自定义hook直接传播了该错误。现在仅在证明同次摘要、替换、来源关联及正常关闭结构完整后继续；下一次模型派发前仍经过官方 `session-checkpoint-policy` 的 flush 持久化屏障。落盘失败不能因此绕过，其他异常仍停止。
3. 完整摘要后按新增工作历史门槛才再次摘要，64KB策略为约2400估算Token；小模型容量封顶。固定系统/任务快照仍进入64KB硬保护，原始工作历史仍持久保存，冷恢复从完整提交记录重建门槛。
4. 组队校验问题会随下一次主动对话提供给模型；任务类型与三人合同示例更清晰。错误不进入保存的用户需求，不自动产生额外付费重试。
5. 恢复新Run的短暂404轮询错误可在后续成功读取后消失；操作失败单独保留，旧Run迟到结果不能回填新Run。
6. 已知费用摘要截断只有在确切 MAX_TOKENS、完整 finish/usage、同次 compaction 全部 wire 请求已结算、原 surface 未改变且没有 summary/replace 时才允许保留原文。用现有 fsync 档案保存 proof，官方 checkpoint flush 必须先成功；未知 fallback、落盘失败和其他错误继续停止。预检及正式派发都保护全部原文，禁止 source 去重与旧读替换，预算变化不能使正式请求缩水。
7. v3 的真实恢复因完整原文超过64KB，在派发前正确拒绝。网页明确调整到128000字节并保存v4，重新批准后执行；新建页面同样改为128000，旧草稿、pending请求、已存方案及运行时旧字段兜底不自动迁移。

未编辑任何员工业务交付文件，未修改DSH依赖，未提高$0.40项目预算。旧版本64KB硬限制保留；v4仅使用经网页明确保存并重新批准的128KB。
