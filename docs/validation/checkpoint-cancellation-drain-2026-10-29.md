# Checkpoint 取消与写入排空一致性

基线 `417b46e`；保留此前停止回归和 PG17 兼容的未提交修改。本批接续已批准的 Checkpoint/任务沙箱计划，先核对已有实现，修复共用任务事务的取消边界；完整恢复来源和新执行模式仍未开放。

## 复用与实际缺口

当前固定 `@deepseek-ai/dsh-session-checkpoint-policy@0.1.5-rc.1` 已在每个员工 Host 安装，负责模型请求前及顶层工具前的会话 flush。已有 API 私有 `prepareCheckpoint`、Handoff 锁、SHA 文件对象、SQL/CAS、ArchiveWriterManager 和原 producer 排空。相关旧实现保留，没有新增保存引擎、沙箱或依赖。

检查发现共用 `LocalRunExecutor.taskTransaction` 存在四类取消边界问题，并实际观察到五项红测试：

- 连接尚未取得时取消，等原连接返回后仍发送一次未启动事务的 ROLLBACK。
- 身份查询的原 SQL 已执行但回应尚未返回时取消，回应返回后仍继续查询并进入保存回调；两项分别覆盖正常及结果不明的回滚。
- 保存回调正在等待时取消，之后仍通过 `persist` 写入实际文件；SQL 回滚无法撤销该物理写入。
- COMMIT 已确认后取消，共用事务仍调用发布回调。实际 Checkpoint 发布器已有自己的取消检查；这里补齐共用边界，不能把此测试描述为已发生的真实 Checkpoint 错误发布。

## 最小修复

只改共用任务事务：BEGIN 派发前标记事务已开始；仅已开始且未确认提交的事务回滚。原连接、SQL/锁等待、费用门禁结束后重查取消；物理 persist 前及确认 COMMIT 后、发布前也检查。保持 project→run 顺序、原错误、原连接单次释放和原有未知结果保护。

取消不替换原 promise，不提前宣布排空。事务已确认回滚后允许释放；回滚失败或 COMMIT 应答不明时继续丢弃连接并锁存原写入失败。已确认的 SQL 提交保留，只拒绝被取消的发布，没有重放、回退费用或制造成功记录。
