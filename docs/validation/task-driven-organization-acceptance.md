# 任务驱动组队：第一段实施与验收

日期：2026-10-18。范围：需求对话中的组织推荐、明确确认、交付标准绑定与证据展示。当前阶段为**已发布 JJ，本地与 JJ 协议验证通过；真实规划质量及新方案重启验收待完成**。

## 复用选择

沿用固定 DSH 0.1.5-rc.1、Cordis 4.0.2、AgentTeams 0.1.20 的调度、任务依赖、员工宿主和返工，不增加另一套执行引擎。沿用现有原生插件注册、沙箱、文件交接、费用、目标封存和恢复。

已核对 [AgentTeams 维护者源码](https://github.com/NanmiCoder/dsh-agent-teams) 与 [LangGraph 官方工作流说明](https://docs.langchain.com/oss/javascript/langgraph/workflows-agents)。已有 Cortex 隔离实测的依赖、身份与分层问题见[原记录](cortex-planning-pilot-2026-10-18.md)。这些框架不能直接提供为伍已有部门的授权及版本绑定，因此本轮只补产品层连接，未重新实现插件或调度框架。

## 已实现

- 原持续对话支持 V2 组织候选：在用户勾选的部门范围内选人、借用员工，或提出新部门。未确认不创建正式部门、员工或项目。
- 推荐包含协作方式及理由、每条交付要求的产出者和检查者。模式标签不冒充已命中的历史模板。
- 明确确认后保存项目；复用已有员工时原部门不变。来源版本变化、部门归档、旧方案、越权和重复确认均由服务端核对。
- 同一对话的新轮次使旧草案失效；乱序返回的旧请求不能重新产生可确认草案。对话轮次随备份保存。
- 交付要求进入方案版本、批准快照和目标封存；AI 调整不得默默删减已确认要求或降低独立检查。
- 运行证据区按要求展示命令证据或员工结构化复核。经理必须等待必要检查，最终文件版本须与检查引用匹配。
- 已保存的旧 V1 对话继续走原团队更新流程。

## 当前限制与后续验收

- 固定响应与本地测试适配器只证明协议和门禁，不证明模型能推荐合理组织或交付合格内容。
- 新方案在 JJ 的真实员工执行、受控重启以及三类真实需求的规划质量仍未验证。本轮没有新的真实运行 ID。
- 恢复字段封存、收据序列化、现有原生返工均有回归；新增标准跨真实重启及实际返工后的证据对应仍需实际运行核对。
- 历史编排模板发布/检索、任意运行中换人或重规划、多个经理与无限递归团队不在第一段范围，尚未实现。
- 本地集成使用单后端 PGlite；HTTP 乱序已验证，不将它等同于多 PostgreSQL 后端锁竞争压力测试。
- 真实验收费用分配见[具体安排](task-driven-organization-real-acceptance-proposal-2026-10-18.md)。旧用量和六笔未知费用保留。

## 使用入口

刷新现有 [JJ 网页](http://127.0.0.1:4312/)：「需求组建」→「组建设置」勾选可参与部门与能力→输入需求并持续补充→检查协作方式和逐条验收→「确认方案并创建项目」→在项目页检查权限、预算与执行条件→批准执行。未勾选已有部门时只形成新部门草案。确认后的项目修改从项目页继续，其他新任务点击「新需求」。
