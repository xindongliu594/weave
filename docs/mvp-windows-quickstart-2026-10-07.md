# 为伍：Windows 网页使用说明

**正常完成和受控重启恢复两条真实路径均已完成。** 两个项目的开发、独立 QA、只读复核、经理报告和五份交付文件均有实际证据。正常路径见[正常 v14 审核](validation/go-normal-v14-real-acceptance-audit-2026-10-07.md)，恢复路径见[受控 v12 审核](validation/go-recovery-v12-final-controlled-audit-2026-10-07.md)。部分供应方费用仍待核对；最新隔离备份已实际恢复，独立备份审核已通过；源码副本状态由配套 code-manifest.json 记录。最终整体结论以随交付提供的验收报告为准。

## 1. 启动网页

需要 Node.js 22.19 及以上的 22.x，或 Node.js 24 及以上。本轮工程验证使用 **Node.js 24.19.0**。在代码目录打开 PowerShell，首次安装运行：

```powershell
npm ci
npm --prefix services/agent-runtime ci
```

根项目和员工运行器分别使用各自的锁文件，已有 DSH/AgentTeams 依赖直接复用。这台电脑已安装依赖，通常不用重装。已有服务时直接打开网页；需要启动时运行：

```powershell
.\start-local-production.cmd
```

启动器构建网页后启动本机服务。保持启动窗口打开，浏览器访问 [http://127.0.0.1:4310/](http://127.0.0.1:4310/)，确认页面顶部后端连接正常。

默认数据保存在代码目录下的 `.data\local`。**这台电脑接续已有项目时，使用现有数据目录启动**：

```powershell
Set-Location 'C:\Users\JJ\.codex\worktrees\f57c\agent_department'
.\start-local-production.cmd '--data-dir=C:\Users\JJ\Desktop\la\agent_department\.data\local'
```

同一数据目录只启动一份服务。结束服务时在它的启动窗口按 `Ctrl+C`，等待退出；下次沿用同一个目录。端口占用时先确认已有工作台是否正在运行；需要另一端口可添加 `--web-port=4321`。修改源码后使用这个生产启动器会重新构建网页。不要删除锁文件、按 Node 名称终止全部进程或修改数据库来启动第二份服务。

## 2. 配置中转站和模型

打开“模型目录 → 接入中转站”，填写名称、API 前缀和 Key，保存。本次使用的 OpenCode Go 前缀是 `https://opencode.ai/zen/go/v1`；已有配置可直接沿用，Key 只在网页填写。

点击“获取模型与价格”，选择实际可用模型。目录未提供价格时依据所用服务的报价填写输入、输出单价；读取目录不发起推理，连接/工具测试会发少量真实请求并计费。

本轮已验证的模型是 **Go · DeepSeek V4.1 Flash**，上游 ID `deepseek-v4.1-flash`、Chat Completions、显式关闭 thinking。已有有效测试结果时无需反复测试。其他 Go 模型是否支持员工工具调用，以该模型的实际工具测试为准。

页面费用是**配置单价 × 已记录 Token 的本机估算**，预留不是供应方账单；缓存折扣、时段价格、套餐扣费以中转站实际账单为准。历史待核对费用仍占用预算。

## 3. 多轮说明需求并确认团队

进入“需求组建”，在输入框下选择“负责组建的模型”。展开“组建设置”，填写项目总预算、人数上限，并选择“员工与后续规划可用模型”。仅使用 Go 时取消旧 Astra、Luna、Sol 的选择。

描述需求，继续补充功能、调整分工和验收标准。首页需求对话不做费用预估、预算预留或单次/每日额度拦截；“项目预算（确认后执行，USD）”只约束执行方案。AI 分配任务预算和调用次数，你确认总额度与方案。对话及候选生成仍由中转站计费，取得的实际用量另存费用历史，不归入新项目的执行预算；未确认的方案不会创建正式团队和项目。旧已确认方案的历史费用规则保留。

例如可以输入：

> 请组建经理、开发和独立 QA，用已选 Go 模型完成仅使用 Node 内置模块的 Todo API。安排开发、独立 CLI/HTTP 测试、复核和经理验收。交付代码、测试、Windows 启动说明与验收报告。服务只监听本机；启动与测试命令写清楚。请在我设置的总预算内分配各任务预算，留出多轮文件上下文及测试修复费用。生成方案后等我确认，再开始执行。

查看页面的“尚未生成”“生成失败”“待确认”“已保存”状态。候选通过校验且符合需求后，点击“确认组建团队”。确认只保存部门、员工和项目；执行还需要下一步批准。

## 4. 批准执行和真实测试

进入“项目与方案”，查看岗位、模型、工具、完整任务依赖、产物和费用校验。已有项目要调整时，在“项目 AI 规划”补充说明，检查费用、生成候选、确认保存，再执行；这一阶段的规划、连接测试和实际执行仍受原单次、项目及每日预算约束。检查任务预算是否包含多轮文件阅读、测试修复和最后交接，不能只看静态估算通过；预算仍由 AI 在你的总上限内分配。

点击“批准并运行”，在“执行记录”查看当前任务、员工状态和预算。返回项目页面会读取最新状态；页面仍显示运行中时可点击“刷新项目状态”。项目结束后才可修改方案或模型范围。

测试命令会逐次请求审批。核对命令、员工和文件版本后批准，等待实际结果。Todo 示例通常包含 `node --test todo.test.mjs` 和 `node --test acceptance.test.mjs`，具体以当前确认方案与审批请求为准。

展开“真实测试结果”查看完整输出、退出码和失败后的复测。测试通过与任务验收是两步：任务应取得宿主交接记录，再由独立复核和经理完成验收。旧通过记录、迟到结果和模型口述不能代替当前文件版本的实际回执。

本机文件与命令使用当前 Windows 用户的权限，在独立项目目录中执行，受网页授权和审批约束；**这不是独立操作系统沙箱**。

## 5. 停止与恢复

在运行页点击“停止运行”，等待状态停止并刷新。要验证服务重启，再到原启动窗口按 `Ctrl+C`，等待退出后按第 1 步沿用同一数据目录启动。

重新打开原运行，在恢复区域点击“检查恢复条件”，核对完成节点、文件、费用、调用次数与执行设备。检查通过后点击“恢复未完成任务”。系统创建关联的新运行档案，继续原批准版本，保留已接受节点和历史用量；已完成节点不重新执行。

“完整重试”会重新执行全部任务，适合明确需要重做的情况。结果不明的命令或外部修改需先核对实际产物，不能盲目重放。费用不明时在“用量与费用”查询账单；日志为空不等于未收费。若选择保留待核对费用继续，预留仍占原预算。

旧运行恢复继续受旧方案额度约束。上下文、任务预算或调用次数不足时，在项目中让 AI 依据真实失败原因重新规划并确认新版本；不反复恢复已耗尽的任务。新方案不会自动替换旧检查点或提高旧运行额度。恢复的未完成任务可以保留现有文件，但新的任务尝试仍要核验当前版本并完成所需真实验证。

## 6. 查看和下载交付

运行完成后核对所有任务及经理验收。在运行页“交付物”预览或下载以下五份文件，依照员工生成的 `README.md` 在下载目录启动并执行测试：

- `server.mjs`：Todo API。
- `todo.test.mjs`：开发测试。
- `acceptance.test.mjs`：独立 CLI/HTTP 验收测试。
- `README.md`：Windows 启停和测试说明。
- `acceptance-report.md`：经理验收报告。

已有真实完成示例可直接打开[正常 v14 运行](http://127.0.0.1:4310/#run/88aa22a9-f887-467c-bf12-91bb57d42361)和[恢复 v12 子运行](http://127.0.0.1:4310/#run/6e860c3c-113c-4245-b400-df85b950769e)。正常开发自修后 **12/12**，QA 和复核各自 **12/12 + 8/8**；恢复路径保留父开发 **6/6**，开发没有重复执行，子 QA 和复核各自 **6/6 + 4/4**。失败与修复记录仍保留。网页主结果使用经理真实交付，原协调回复折叠保留，执行列表显示“已完成”。运行页还提供 Run ID、审批、完整真实测试输出及“导出完整追溯”。

员工验收报告中的部分版本编号、实读文件数量和输出长度有叙述误差，原报告没有被代写或修补。核对时同时查看上述独立审核和完整宿主回执，它们标明准确版本、文件 SHA 与测试结果。

文件存在并不代表项目验收完成。运行仍失败、任务未接受或缺少经理报告时，应保留现有文件与失败原因，继续网页恢复或方案调整；用户无需手工修改数据库或补写交付物。

知识资料通过“知识库”录入，并在部门与员工中明确授权后纳入批准方案。运行引用批准快照中的固定版本；后来编辑资料不会替换旧运行的引用。本次恢复已实际验证：批准时固定 v3，目录升 v4，重启后的 QA 与经理仍读取 v3；QA 私有正文只授权 QA。当前验证采用关键词检索，语义模型尚未安装，不能承诺语义召回。

Todo 示例使用内存存储，结束它的进程后 Todo 数据消失；工作台的项目、交付文件、检查点与费用记录独立持久化。最新完整备份已在独立目录恢复，两个最终项目的十份文件逐字节与 SHA 相符，正常项目的开发测试在隔离副本中 **12/12** 通过；原环境没有被覆盖。[独立备份审核](validation/mvp-full-offline-backup-independent-audit-2026-10-07.md)通过。源码包上一级 code-manifest.json 提供字节与 SHA 清单，实际交付位置见配套交付记录。
