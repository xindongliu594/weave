# 10 风险与冻结决策

## 已冻结决策

| 决策 | 选择 | 原因 |
|---|---|---|
| 部署 | 本地 Docker Compose | 优先完成可运行闭环 |
| 主语言 | TypeScript | 与 DSH/Cordis 及前端共享类型 |
| 数据库 | PostgreSQL + pgvector | 同时满足业务数据和初期向量检索 |
| Runtime | DSH，经 Adapter 接入 | 利用插件和多模型能力，同时保留替换空间 |
| 单部门协作 | dsh-agent-teams | 已具备 Captain、成员、DAG、消息和模型路由 |
| 权威状态 | 产品数据库 | 不绑定 Runtime 内部持久化格式 |
| 计划执行 | 人工批准后运行 | 控制成本和风险 |
| Agent 配置 | Run 时快照 | 保证历史可重现 |
| 默认创建模式 | 主模型推荐、用户可编辑 | 降低使用门槛并保留控制权 |
| 约束执行 | 确定性校验器 | 不依赖模型自我约束 |

## 风险登记

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| DSH prerelease 接口变化 | 集成返工 | 锁版本；所有调用经过 Adapter；建立契约测试 |
| 插件和 DSH 版本不匹配 | 无法启动或行为异常 | 保存兼容矩阵；升级先跑 Spike |
| 不同模型工具调用差异 | 员工执行失败 | 模型能力目录；配置时校验；准备 fallback |
| 文件状态与数据库状态分叉 | 展示错误或任务丢失 | 数据库保存事件；定期 reconciliation |
| 多 Agent 写冲突 | 交付物被覆盖 | 独立工作区、任务范围、合并/审查阶段 |
| RAG 越权 | 数据泄漏 | 检索前权限过滤；负向权限测试 |
| 无限循环和高费用 | 成本失控 | 轮数、并发、时间和费用硬限制 |
| Runtime 进程退出 | 任务悬挂 | 心跳、租约、恢复扫描和 NEEDS_ATTENTION |
| 密钥进入日志 | 严重安全问题 | 引用式密钥、统一脱敏、安全测试 |
| 主模型虚构模型或能力 | 方案无法执行 | 只允许 ModelCatalogSnapshot 中的 ID |
| 主模型过度组建团队 | 费用和延迟增加 | 最大人数、并发、预算和小任务单 Agent 规则 |
| 费用估算不准确 | 实际超预算 | 后台重算、实时累计和硬停止 |

## 开工 Go/No-Go

Go 条件：

- DSH Spike 的关键项通过。
- 至少两个 Provider 的模型能被不同成员稳定调用。
- 可以停止运行并获得确定状态。
- DSH Adapter 契约不泄漏内部类型。
- 团队接受第一版范围和非目标。

No-Go 后的替代方案：保留产品控制面、数据协议和 UI，将 Runtime Adapter 换成 Microsoft Agent Framework、LangGraph 或自建执行器。业务层不应因此重写。
