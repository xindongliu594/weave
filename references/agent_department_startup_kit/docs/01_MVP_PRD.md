# 01 MVP 产品需求

## 产品目标

提供一个本地运行的多模型虚拟部门平台。普通用户只需描述项目需求并设置费用、Agent 数量、并发和权限上限，主模型自动生成部门、员工、模型与任务方案；高级用户可以修改生成方案或完全自定义。

## 核心用户流程

1. 用户提交项目需求，选择经济、均衡、高质量或自定义偏好。
2. 用户设置费用、Agent 数量、并发、时限和审批上限。
3. 组织规划器把真实模型目录和硬约束交给主模型。
4. 主模型输出结构化组织方案，不立即执行。
5. 确定性校验器检查模型、能力、预算、权限和任务 DAG。
6. 推荐模式下，用户查看、修改并批准方案；全自动模式只运行低风险合规方案。
7. 系统创建经理与员工，员工执行任务，经理审查并汇总。
8. 用户查看交付物、执行轨迹、费用和引用来源。

## MVP 功能清单

### P0：必须完成

- 部门 CRUD 与归档。
- 推荐方案、全自动、完全自定义三种创建模式。
- 项目需求、执行偏好和硬约束表单。
- 主模型自动生成部门、角色、模型和任务 DAG。
- 确定性模型、预算、权限及 DAG 校验器。
- 方案版本、用户修改记录和最终批准快照。
- 员工 CRUD；每部门最多 5 名员工。
- 经理和员工分别配置 Provider、Model、推理强度。
- 角色说明、系统约束和预期输出格式。
- 公司级与部门级知识库。
- 提交任务、生成计划、人工批准、运行和停止。
- 任务依赖、状态、负责人、重试和最终结果。
- Agent 消息、工具调用、模型用量和错误日志。
- API Key 服务端保存；前端不回传明文。
- 单机 Docker Compose 启动。

### P1：MVP 后补充

- 员工私有知识库。
- 部门模板和员工模板。
- 主模型/备用模型。
- 任务预算和部门日预算。
- 跨部门任务。
- 文件交付物预览。

### 非目标

- 第一版不支持公开 SaaS 多租户计费。
- 不允许 Agent 无审批对外发送消息、部署或删除重要数据。
- 不承诺任意 DSH 新版本自动兼容。

## 业务规则

- 一个部门只有一位经理，但经理也是可配置 Agent。
- 一个部门同时最多运行一个 TeamRun；后续再开放并行运行。
- 修改员工模型只影响新 Run；运行中的 Run 使用创建时快照。
- 删除员工采用归档，历史 Run、消息和交付物必须保留。
- 部门经理只能分配已授权的工具、知识库和预算。
- 推荐方案模式必须由用户批准；全自动模式仅允许低风险且校验通过的方案。
- 模型只能从后台提供的真实模型目录中选择。
- 模型不能提高预算、扩大权限或改变审批策略。

## 页面范围

- 部门列表
- 部门编辑器
- 项目需求与约束页面
- 自动生成方案预览及编辑器
- 员工配置抽屉
- 模型选择器
- 知识库管理
- 任务提交与计划批准
- 运行详情：任务 DAG、成员状态、消息、用量、交付物
- 系统设置：模型 Provider、密钥、限额

## 成功指标

- 新用户 10 分钟内创建并运行第一个部门。
- 三 Agent 标准任务成功完成率达到 90%。
- 运行失败时 100% 可定位到 Agent、模型调用或工具调用。
- 停止操作在 10 秒内使新模型调用停止进入队列。
- 任一交付结论可以追溯到任务、消息和知识来源。
